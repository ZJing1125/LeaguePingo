# 本地产物双版本管理

本项目仍为本地开发/验收，不区分独立的“开发版”和“验收版”程序。只保留当前版和回退版及各自证据。验收是同一文件的状态变化，不复制二进制。管理入口是 Git Bash 中的 `scripts/build.sh` 和 `node scripts/artifacts.mjs`；不常驻后台，不影响游戏运行。

多主机边界：本文件的“本地”指运行管理脚本的主机。远程开发、Windows 构建与游戏验收可以在不同机器上进行；配置和验证范围见 [环境说明](ENVIRONMENTS.md)。不跨主机复制验收清单，不据远端构建结果清理游戏电脑，不在网络共享的产物目录使用本机进程保护。成功dev构建提供[迭代下载包](CLOUD_BUILDS.md)，只有程序、构建说明和校验值；不复制本机留存清单，不自动部署或验收。

## 后续构建

配置 README 的工具路径后执行：

```bash
bash scripts/build.sh
# 也可指定尚不存在的输出文件（仅允许 bin/leaguepingo*.exe）
bash scripts/build.sh bin/leaguepingo-dev-20261019-v10.exe
```

默认名称包含 UTC 时间和提交号，不覆盖任何已有程序；同秒同提交冲突会直接拒绝。脚本获取独占构建锁，运行完整验证，再编译、检查 PE 文件格式、计算校验值、登记新版本，最后清理旧版。浏览器截图自动输出到该版本的证据目录。PE 格式检查只排除明显无效/部分输出，不冒充真实桌面验收。

完整验证会核验正式图标资源，并生成当前 amd64 的 Windows syso（图标、既有 DPI manifest 与版本信息），供随后编译链接。热重载同样生成资源；对象文件已忽略，不能单独交付。维护与实机图标验收见 APP_ICON.md，普通构建无须额外手工生成图标。

构建之后补充的截图、无脚本合成页面快照或性能 CSV 应放在对应 `artifacts/<程序名>/` 的直接子级，并用 `node scripts/artifacts.mjs attach-evidence --file bin/<程序名>.exe --apply` 纳入同一版本的清理清单；只接受当前/回退版的 PNG/HTML/CSV，已登记文件被改写时拒绝悄悄更新哈希。HTML 只用于浏览器合成桥接生成的离线界面复核，不得包含真实账号、鉴权、接口原文或可执行脚本。目录内的其他文件和隔离配置不自动登记。没有登记的外部诊断输出不在自动清理范围内。

首次克隆且 `bin` 无二进制时，可初始化空清单并构建；已有程序但清单丢失时拒绝自动接管，需要先人工核对并恢复清单。不要重复运行历史 bootstrap。禁止直接使用 `go build` 交付程序；上游安装器/签名/Docker 入口目前明确拒绝执行。标准 `wails3 build`/任务入口统一转到 `build.sh`，热重载单独使用 `artifacts/hot-reload/` 的固定临时文件，不进入交付清单。

### 规则、入口与交付检查

根目录 `AGENTS.md` 是后续开发者/助手必须读取的项目约定。`scripts/workflow.mjs check` 检查标准任务路由、验证/编译/清理/审计顺序、热重载隔离和规则文件关键约束；配套测试使用真实 Wails dry-run 展开任务和临时目录中的模拟构建脚本，防止入口变更回退。检查器针对当前受限任务格式，不是通用 YAML 解析器或防篡改沙箱；改入口需同步维护规则与测试。

交付构建前执行 `node scripts/artifacts.mjs audit --allow-empty`，构建登记/清理后再执行 `node scripts/artifacts.mjs audit`。审计只读核验清单中程序/证据哈希，递归检查 `bin` 中未知 `.exe`，并只允许运行中的受管旧版超额暂留。发现未登记程序、清理未完成、文件缺失/变更时失败，不自动删除未知文件。`current` 先审计再返回当前路径，`scripts/run.sh` 据此启动，不假定固定文件名。

热重载通过 `scripts/dev.sh` 生成独立临时文件，不运行完整交付验证、不登记、不清理回退版，但与交付构建共享 `bin/.build-lock`，避免绑定和前端文件并发生成。临时程序仍运行时不覆盖、不结束它；如与当前助手单实例冲突，由用户决定是否退出旧助手。非 Windows/amd64、`DEV=true` 交付和额外标签均拒绝；Wails 包装器跨架构参数为 `GOARCH`，不是 `ARCH`。

仓库外手动编译或特意修改脚本仍能绕过流程；本方案保证的是标准入口统一、常见回退可测试、未登记产物不能通过正常交付检查，不承诺对拥有本机权限的操作做强制封锁。GitHub Actions已按优化清单Q1接入`.github/workflows/ci.yml`，仍只走受管build.sh；远程产物不自动部署或变更游戏电脑的验收状态，见ENVIRONMENTS。

### 留存与验收规则

1. 新构建默认“待验收”。保留最新构建和它之前最近一个已验收版；没有已验收记录时暂保留紧邻的上一构建，不称其已验证可用。
2. 新版待验收/失败时继续修复构建，淘汰旧候选，保留最近已验收版。不能把失败候选提升为回退依据。
3. 用户明确验收通过后，再登记当前版：

   ```bash
   node scripts/artifacts.mjs accept --file bin/leaguepingo-dev-20261019-v10.exe --apply
   ```

4. 之后构建 v11，已通过的 v10 成为回退版；更早程序及其登记证据被永久删除。验收仅针对该次修复范围，不扩展为所有模式/账号/性能全部通过。
5. 验证或编译失败不会登记新版本或淘汰可用旧版；本次失败的部分输出和截图会尝试清理。无法确认进程状态、未知文件或异常中断时宁可保留残留并报告。

## 预览、清理与安全边界

```bash
# 只读预览；无参数也是预览
node scripts/artifacts.mjs
node scripts/artifacts.mjs clean
# 按受管清单永久删除，不进回收站
node scripts/artifacts.mjs clean --apply
```

清理前核验保留程序和待删文件的 SHA-256；文件变更、保留程序丢失或路径异常时停止。只允许明确登记的 `bin` 程序/历史证据和 `artifacts` 证据路径，拒绝目录穿越、链接/junction、重复清单和越界路径；逐文件删除，只移除空证据目录，不递归删除项目目录。源码、配置、工具缓存和未登记文件不被扫描删除。

Windows 进程路径通过只读 CIM 查询核验，不读取命令行/凭据，不修改 PowerShell 执行策略。旧版仍运行时，连同它的证据一起跳过；不会结束进程。此时可以暂时多于两个版本，用户退出旧版后再清理。进程查询失败或存在无法解析路径的助手进程时，整个清理停止。Windows 文件占用错误也会保留文件并报错。

独占锁防止脚本并发修改清单/重叠构建。崩溃遗留的 `bin/artifacts.lock` 或 `bin/.build-lock` 不自动强删，需确认没有构建/整理进程后人工处理。清单损坏或遗留 `artifacts-next.json` 同样停止，不通过“重新扫描删除所有旧文件”来恢复。

永久删除的二进制和原始证据不能从回收站恢复。源码仍在 Git，但重新编译不保证得到相同字节；已删证据也不能凭历史结论重建。

`scripts/workflow.test.mjs` 同时验证入口路由、策略变异拒绝、实际 Wails 别名（隔离模拟工作区）、未支持入口失败和交付审计。入口测试不在真实项目中执行产品构建。新的热重载与实际桌面启动链路仍需后续显式开发运行验证。
