# S1 按住快览与输入边界

S1代码改动已实施；Windows自动化结果以对应提交CI为准。真实国服、反作弊环境、窗口焦点与整局体验仍待游戏电脑验收，不因回调变短而宣称兼容性已通过或游戏零开销。

## 实现

Microsoft的[LowLevelKeyboardProc说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)要求低级钩子尽快转交工作并返回，并指出调用时异步键状态尚未更新。本实现不在新捕获按下时立即用GetAsyncKeyState否定它；仅配置初始化或后续定时检查才取物理状态，避免首按被旧状态误清除。

- Windows低级键盘钩子仍在专用消息线程；所有分支将原始参数原样交给`CallNextHookEx`并保留下游返回值，不吞键、不发送按键、不模拟点击。
- 只处理启用的当前配置键（Esc下方物理键或F8/F9/F10）。注入事件、无关键和非按下/松开消息直接转发；不保存扫描码、输入顺序、文字或原始事件。不跟踪其余三个候选键。
- 键盘回调仅作物理键映射、原子状态更新、单槽非阻塞通知和既有耗时聚合。前台变化回调仅使当前按住状态失效并通知；两者均不获取应用锁、不查进程、不读按键状态、不操作定时器或调用Wails。
- 独立工作任务消费最新状态，使用有限查询权限判断前台可执行文件名；不读命令行、鉴权或游戏内存。仅在允许的对局阶段、当前键处于按住状态时查询前台进程；无按住时没有该任务的周期进程读取。
- 原有150毫秒丢松键/前台事件兜底移入工作任务。持续按住时才有定时检查；关闭、离局、退出取消显示。反引号的兜底读取按前台线程键盘布局映射物理scan 0x29，避免把其他布局的VK_OEM_3误当同一键。
- 单个原子字保存当前配置、按住状态和版本，通知队列容量为1；没有按键事件积压。进程读取返回后复核同一版本，松键、切前台、改键、禁用、阶段改变和停止使旧结果失效；长按重复不重复排队。切出再切回或启用时已按住，须先松开再按。

主窗口与托盘已有“显示／收起游戏助手”，不依赖低级钩子或全局快捷键注册成功；手动窗口保持可交互，松开临时键不关闭它。设置页明确说明监听范围和备用入口。首次创建WebView仍由原控制器复核按住/阶段/前台，显示只使用已有资料，不增加网络请求。

诊断`performance.keyboardCallback`仍仅保存配置键非注入事件的次数、total/mean/max微秒，排除下游钩子链；不记录键值或输入流。它只衡量回调自身，不是端到端快览响应时间或反作弊判断。

## 验证范围

Linux可跑状态合并、无应用锁/无分配回调路径、迟到结果隔离、重复键、缺事件恢复、并发配置与工作任务退出测试；静态回调契约防止把锁、进程读取和定时器搬回回调。Windows回归使用合成结构直接调用回调ABI，核对负code、非action、注入/无关事件、布局键、重复、松键和空指针均转发原参数并保留下游结果；不注册真实全局钩子、不生成系统输入。它不证明腾讯反作弊兼容。

`bash scripts/verify.sh windows`只在原生Windows amd64执行；Linux明确拒绝，另行选择portable。Windows测试程序的交叉编译不等于执行，不作为用户交付。
