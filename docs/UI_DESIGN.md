# LeaguePingo 桌面界面规范

## 目标与信息层级

以玩家资料、战绩和对局比较为核心。深色中性背景，青绿只强调品牌、当前入口和成功表现；失败使用低饱和玫红，未知使用灰色。胜负同时显示文字，不只依靠颜色。

字号：姓名和页面标题 19–20px、关键指标 15–16px、正文 12–13px、辅助时间和标签 11px。数字使用等宽数字特性。图标使用本地 SVG，游戏素材使用已打包图集；不引入远程字体、持续动画或自动详情请求。

## 桌面窗口外壳

主窗口使用 Wails 3 无边框窗口，替换灰色系统标题栏；原生尺寸约束、边缘缩放、系统阴影及 Windows 11 圆角由 Wails/Windows 保持。36px 深色标题栏贯穿窗口，左侧为青绿 P 标识、LeaguePingo 和用途，右侧为最小化、最大化／还原、关闭。品牌移到标题栏，侧栏直接展示导航，避免重复占位。

标题栏空白和品牌区可拖动，双击切换最大化；窗口按钮使用 `no-drag`，图标内不截获指针。按钮有中文可访问名称、键盘焦点和悬停态，关闭悬停使用玫红，并明确提示收起到托盘。关闭调用原生 WindowClosing 钩子；真正退出仍通过托盘菜单。托盘点击、菜单打开和重复启动都显示、还原并聚焦主窗口。

最大化／还原图标跟随 Wails 原生事件及当前窗口状态，不使用固定轮询；失焦时品牌降低强调。设置遮罩从标题栏下方开始，保留窗口控制；设置打开期间窗口按钮退出 Tab 顺序，鼠标操作不抢走输入焦点。快览保留原有独立紧凑标题栏，不重复加入主窗口标题栏。

浏览器检查只验证自定义标题栏呈现、模拟运行时调用、键盘操作和布局；Windows 边缘缩放、拖动、贴靠、系统菜单、关闭到托盘和跨屏 DPI 仍需原生验收。当前未启用实验性 WebView2 composition hosting，不承诺自绘最大化按钮悬停时出现 Windows 11 Snap Layouts 面板。

## 三个工作界面

- 战绩：导航默认收起至 68px，可展开；头像/身份/等级与双排位资料集中在头部。左侧近期表现与英雄样本，主列表保留模式、胜负、时间、英雄、KDA、技能和终局装备。双方详情显式读取，样本说明折叠，记录排除提示就近展开。
- 当前对局：双方按相同布局展示。姓名、准备状态、近五场与胜率/KDA对齐；打开详情时名单保留可点击空间。抽屉的模式/场数/页码/展开和分页缓存与玩家战绩页独立；本局统计不受显式查询筛选影响，新局重置抽屉，不重置玩家标签。房间阶段使用房间成员/对手未确定，不声称已有双方十人。
- 快览：两列各五人，姓名/英雄为第一层，胜率、KDA和近五场为第二层。公共时间与快捷键集中底部；单独旧资料、失败仍就近标记。标题拖动，按钮不参与拖动，保持鼠标可操作。

## 状态和验收

玩家标签使用单一顺序焦点，支持左右方向键循环、Home/End 和 Delete；当前标签关联对应玩家面板，关闭后焦点保留在相邻标签，最后一个关闭后回到搜索框。设置打开时背景不可交互，Tab 不离开面板，关闭后焦点回到设置入口。

每局开局补齐时，名单说明显示一轮及时间/人数限制，已排队玩家为“正在获取”；复用赛前已准备资料，只补缺失姓名/首批战绩。结束/失败明确提供手动查询，不长期显示“待准备”。姓名缺失时可显示英雄名及“姓名未获取”，不把占位复制为完整 ID；姓名到达后同步名单、详情、标签和快览，与历史新旧分别处理。标签横向滚动条不挤压文字，当前标签自动滚入可见区域。

战绩行明确 1.35 行高和 74px 最小高度，减少系统字体差异造成的首屏密度变化；仍以五条完整战绩的几何检查为准。双方详情复用共享文字、边框、次要文字和选中态 tokens。组件状态预览和迭代方式见 [FRONTEND_GUIDE.md](FRONTEND_GUIDE.md)。

缺失字段显示 —，段位未获取不等于未定级。真实头像来自核验后的本地资源，获取不到保持明确占位，不用当前英雄冒充。搜索失败保留资料，错误只归属发起操作的玩家；资料字段保留时间并标旧值，历史/资料更新相互独立。

战绩展开补充地图、明确位置、符文文字和提前结束信号；这些只是已获取字段，不增加自动整场请求。快览胜率/KDA 常显标签与每人样本数，不能依赖悬停才能辨认指标；有效样本分母可悬停查看。后续真实数据验收仍需核对长名字、局部失败和不同分辨率，当前没有符文位图或自创评分。

浏览器合成回归验证：1280×800、100% CSS 缩放至少五条完整战绩；无需展开即可看到七个装备槽与两个召唤师技能；880×620无根级横向溢出；540×660正常十人全部就绪时完整可见；切人、分页、详情、快捷键和设置交互保留。主窗口预算包含 36px 自绘标题栏，工具栏 50px、资料区至少 80px、历史工具行至少 46px，战绩行的字号和内容保持原有密度。合成截图输出本地 `artifacts/ui-review`，不提交玩家资料。

快览最小原生尺寸 400×360：500px 以下指标与近况分行，允许纵向滚动但不横向挤压；不要求最小高度仍把十人全部塞进一屏。合成截图不等于 Windows DPI、独占全屏或真实对局验收。后续以真实账号可用字段和同尺寸对照继续调整。

## 实机反馈后的浏览交互（2026-10-17）

- 固定保留单双排、灵活排位、极地大乱斗、海克斯大乱斗（2400）；选项是否出现不依赖首批历史。查询、刷新战绩、更新资料各自显示操作状态，不因刷新把顶部按钮标成“查询中”。
- 左侧近期表现提供 10/20/30/40/50 场选择，默认 20，紧邻实际/目标数量和模式。对局抽屉提供相同选项。胜率、KDA、近况、常用英雄只用所选模式最近的实际样本，不随列表翻页变化。
- 分页内嵌在战绩面板内，与列表共用边框，只滚动列表，不贴窗口底边；包含上一页/下一页、当前页、当前记录范围和每页 20 场。增加页码输入和“跳转”，支持回车，非法输入就近提示且不请求。窄抽屉允许控件换行，不横向溢出。
- 尚可继续查找时显示已找到页数，不冒称总页数；来源受限时仍只显示已找到范围。远页按需查找，单轮暂停说明目标页，继续保留目标；查不到目标时保留当前页。切换模式/场数或刷新回第一页，切换玩家保留各自浏览状态。
- 显式样本查找持续到所选模式目标数量、来源耗尽/受限、最近 1000 条混合记录或 90 秒预算，不每五页暂停。进度与停止入口保持可见，切人/离开工作区停止后续扫描；超时/失败可继续/重试，断线只看缓存，耗尽则按实际样本分析。远页跳转保持每轮五请求/15 秒限制。刷新后不悄悄补拉不足的样本，提供“补齐样本”按钮。
- 合成回归保留 1280×800 未展开时至少五条完整记录，新增 880×620 主窗口/抽屉内嵌分页可见与无横向溢出检查；截图在本地 `bin/ui-paging-20261017-*.png`，不代表已完成真实 DPI/游戏验收。
