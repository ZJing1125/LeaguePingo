# 本局英雄攻略（BUG-0072）

用户已批准接入OP.GG官方MCP，并在BUG-0073批准优先接入海克斯大乱斗公开专页。Go直接访问`https://mcp-api.op.gg/mcp`，不要求安装Node、MCP工具或大模型。客户端仅发送英雄、分路、模式和zh_CN语言；不发送任何PUUID、玩家名、房间、客户端授权或比赛编号。无自建服务器，仍需要联网。

## 范围与入口

主程序当前对局默认紧凑攻略摘要，可展开完整攻略，客户端侧栏新增玩家资料/本局攻略切换，手动局内快览可切换查看缓存的核心装备、符文与至多两条要点，默认及按住/开局快览仍展示完整双方卡片，不因新增攻略挤掉十人名单。选人未确认/仅预选不查询；分路缺失时请用户选择，不从英雄猜分路。已有明确分路时尝试匹配唯一同路对手，可手动改选实际敌方英雄；重复分路不自动匹配。对手从当前名单消失时清除旧选择。所有窗口通过有序revision内存事件共享一份结果；切主题、显隐、页面与重复快照不请求OP.GG。

队列420/440/450分别映射ranked/flex/aram，mapId/gameMode明确冲突时拒绝映射；400/430/490显示排位来源的峡谷参考，非该模式专属统计。海克斯大乱斗按下述独立路径处理，竞技场与轮换模式按BUG-0075独立处理，其他队列不按地图猜成普通大乱斗。普通大乱斗的工具协议强制position，内部固定mid作为请求占位，界面不把它显示为推断分路。分路对位工具无模式参数，仅用于单双排峡谷参考；灵活只使用独立flex分析，不能将无模式的对位正文包装成灵活专属攻略。

## 数据与执行

`internal/guides`包含固定MCP初始化/只读tools/call协议、响应归一化和独立Service。标准模式在进程内复用协议版本与`Mcp-Session-Id`最多15分钟；旧会话被服务以400/404/410明确拒绝时只重建一次。基础分析与对位分别加载，先显示已有基础内容，再补正文。每内容任务整体8秒、单HTTP5秒；当前查询稳定800ms后才开始，旧选择/账号/连接/对局/阶段变化取消并拒绝迟到发布及缓存写入，最多2个网络任务占位。30秒失败冷却，显式刷新也不突破冷却；无自动失败循环和批量全英雄扫描。与玩家战绩scheduler及自动接受/赛后动作通道独立。

MCP响应可能为JSON或“class字段定义＋位置构造器”的压缩文本。压缩解析器仅支持声明过的构造器、列表与标量，限制大小2MiB、深度64和节点10万；不执行返回内容。工具文本通过Vue转义呈现，不使用v-html。返回的样本缺失保持未知，已知零胜率保留零。技能整数槽位转换Q/W/E/R，中文物品/符文名由服务提供，本地官方图标缺失沿既有占位。

英雄英文映射由已有Riot Data Dragon头像manifest生成并处理命名差异；新英雄需更新随包映射。缓存只保存归一化公共攻略，查询包含mode/champion/position/opponent/客户端patch（可空）；实际来源版本保留在结果。内存/磁盘最多128条，每条256KiB，6小时新鲜度、超过7天丢弃。缓存先显示再后台更新；刷新失败保留有效缓存，没有缓存时显示固定降级提示及当前英雄原文链接。版本明确不同时提示差异，不能称为当前版本攻略。服务接口不接受指定历史版本，本地patch未知时如实标来源版本。无源码/文章/视频批量复制，保留OP.GG来源和原文链接。

设置页提供独立“启用OP.GG英雄攻略”开关，默认开启且旧设置按开启迁移。关闭后立即取消在途读取并隐藏所有攻略入口；再次开启只按当时当前快照恢复，不预取其他英雄。设置说明明确第三方只收到模式、英雄、位置、对位英雄和语言，不发送玩家名称、PUUID、房间、比赛或客户端授权。

## 验证与限制

单测覆盖受限文本解析、恶意/异常响应拒绝、JSON/SSE握手、MCP会话复用与失效重建、字段和授权隔离、模式变体拒绝、总超时、缓存复用/失败保留、功能开关、旧设置迁移、未知分路、对手合法性、重复快照、晚到请求与换连接。

可显式运行`LEAGUEPINGO_TEST_OPGG=1 go test ./internal/guides -run TestLiveOPGG -count=1 -v`核验公共服务，不读取游戏客户端。本批已实调ranked/flex/aram，以及GALIO对AHRI的mid攻略，中文装备/符文和对位正文归一化成功。真实网络结果只证明本次服务可用，不保证所有英雄/对位均有足够样本。

浏览器`frontend/tests/guides.cjs`为合成桥接，验证280侧栏与880/1280主窗、主题、来源/样本、备选方案、失败缓存保留、模式不可用、位置操作、跨窗事件和分组标记。Windows原生外链、选人换英雄、客户端版本字段覆盖及真实游戏体验仍需实机验收；本批Linux不交付exe。

## BUG-0073：海克斯大乱斗优先批次

队列2400（[Riot队列清单](https://static.developer.riotgames.com/docs/lol/queues.json)）独立映射aram-mayhem，已知地图须12，模式须ARAM或ARAM_MAYHEM；未知/冲突及其他变体不套用。source修复gameData.queue.gameMode/mapId与顶层map，保留旧结构回退；同响应明确冲突拒绝映射。实际国服模式字段仍待实机对照。

官方MCP的lol_list_aram_augments当前仅返回tier>=3，会遗漏OP/1/2级，不能作为完整推荐源。独立适配固定读取`https://op.gg/zh-cn/lol/modes/aram-mayhem/{公开英雄slug}/augments`与`/build`；各一次GET，使用产品自身User-Agent，不发送玩家身份、Cookie、客户端授权，不跟随重定向，不加载页面脚本/字体/图片。每页最多3MiB、整体沿用8秒与HTTP5秒，无自动重试。只解析Next Flight脚本里的JSON字符串和JSON记录，校验对应页面canonical，限制引用深度64/节点10万及循环，结构变化明确失败。与MCP同用现有缓存/取消通道；没有批量英雄抓取或新增运行依赖。

展示源梯度0–5（0标OP级），与品质1/4/8（银/金/棱彩）分开。表现分、热度分原样保留为分值，不能解释成胜率/选取率，也不能用表现分排序冒充源梯度。列表按梯度升序、同级热度降序；缺少名称/说明的条目跳过并标数量。强化数据没有明确版本、胜率或样本量，这些字段保持未知；出装页版本仅来自该页标题，不能由请求的客户端版本或素材版本推断。出装只保留公开页方案（没有样本/胜率）；技能显示页面提供顺序，不补满18次。传统符文与峡谷单英雄对位不用于海克斯。

MayhemAugments提供搜索、品质筛选与至多三个手动候选的效果/梯度/分值比较。GuideCandidates仅写共享内存状态，核验scope、英雄、ID集合和重复项，发有序事件，无网络取数；主窗/280侧栏/手动快览同步。换英雄/对局清空旧选择，同英雄刷新复核ID。比较控件不抢焦点，开局/按住快览仍保留十人卡。自动识别游戏里实际三选项尚未实现。

修复内存命中也执行七天过期检查，磁盘读取后同样执行128条上限；失败保留有效缓存，部分页面失败保留已取得部分并说明，原文入口独立于成功状态。

显式公共验证：`LEAGUEPINGO_TEST_MAYHEM=1 go test ./internal/guides -run TestLiveMayhem -count=1 -v`。本批核验加里奥、拉克丝、艾希、德莱厄斯、索拉卡：各182–207项有中文元数据的强化（含0–2级）、四组出装/技能方案及15步来源加点。该范围不能代表全部英雄、当前国服版本或整局性能已验收。页面适配依赖网站结构，需要维护。

验收包括：普通ARAM与海克斯切换/未知变体拒绝；五类英雄与对应原文核对；缺中文/零/未知分值；三候选跨窗/搜索筛选无取数；主窗880/1280、侧栏280与快览1100×640；浅深主题、换英雄、断网缓存与过期。浏览器和Go为合成验证，Windows国服选人/实际网络/原生外链/FPS仍未验证，不生成交付exe。

## BUG-0075：其他模式批次

按Riot队列清单识别：900/1900为无限火力（map11/URF），1300极限闪击（map21/NEXUSBLITZ），1700/1710竞技场（map30/CHERRY）。只拒绝明确冲突，缺字段不按地图猜模式；1010雪地URF和其他未知变体不冒充标准模式。攻略不依赖固定5v5阵容分母，不为轮换/竞技场推断分路或调用峡谷单对单正文。

实际探测官方MCP的urf/nexus_blitz存在分路参数矛盾：mid得到The position must be NONE，NONE又被枚举校验拒绝。因此固定读取对应`/lol/modes/urf/{hero}/build`和`/nexus-blitz/{hero}/build`公共中文页，每模式只请求一次。复用受限Flight解析；符文取rune_pages首个明确方案的primary/secondary/stat_mod ID，不从图片位置推断。来源页面当前为16.04/13.23，必须显示版本参考，不能冒称当前客户端版本；版本比较将16.04/16.4.1归一到同一补丁号。公开页无出装样本时保持未知。离线失效/缓存预算不变。

竞技场使用`/arena/{hero}/augments`和`/build`。强化数据是各品质独立推荐表（源字段rareity），没有海克斯OP梯度或表现分；仅显示来源胜率与样本，胜率沿用站点定义，不等于夺冠率。最多三个候选通过既有内存事件共享。出装增加棱彩装备，搭档表保留其原始组合胜率/场数，不能包装成针对敌方个人的对线攻略。缺中文元数据跳过并报数量，没有传统赛前符文。公开页只代表站点当时收录的推荐项，不代表全体强化。

`LEAGUEPINGO_TEST_EXTENDED_MODES=1 go test ./internal/guides -run TestLiveExtendedModes -count=1 -v`实际核验：加里奥URF/Nexus分别4组装备/技能、9枚符文，来源16.04/13.23；竞技场加里奥、卡莎、德莱厄斯分别39/41/40项强化、3组出装、5项搭档数据，来源16.21。公共成功不能代替Windows国服真实选人、实际队列/模式字段、网络和游戏性能验收。

自动识别当前三个强化选项仍无已核验的现有LCU/Live Client Data通道；[Overwolf文档](https://dev.overwolf.com/ow-native/live-game-data-gep/supported-games/league-of-legends/)有其独立运行时augments事件，这不等于纯本地Wails助手可直接调用。当前保留手动候选比较。Windows屏幕OCR需要真实画面和原生实现验证，尚未交付。未把这一待验证能力或P1实机验收标成完成。
