# 分阶段游戏助手（BUG-0054）

BUG-0067起，主程序对局室提供当前对局资料与最近赛后复盘两个独立入口；客户端侧栏与局内快览复用同一个辅助窗口。默认左侧/320逻辑像素；深浅主题、C款图标、独立排位统计口径沿用现有产品。当前实现主机为Linux；目标平台仍为Windows amd64。

## 阶段与窗口

| Phase | 行为 |
| --- | --- |
| Lobby/Matchmaking/ReadyCheck | 侧栏只显示实际房间成员 |
| ChampSelect | 侧栏只显示我方，英雄/预选随快照更新 |
| GameStart | 隐藏侧栏并准备名单；游戏前台、名单与前端就绪即可自动展示快览 |
| InProgress | 沿用载入阶段的同局一次资格及截止时间；之后按住键查看 |
| Reconnect | 隐藏临时窗，不续自动展示资格 |
| WaitingForStats/PreEndOfGame/EndOfGame | 隐藏快览，冻结并同步赛后记录 |
| 断线/观战/空闲 | 不自动显示辅助窗口 |

从首次GameStart起最多等待45秒，直接局内启动则从首次InProgress起计；不在用户很晚切回游戏时突然补弹。选人已出现比赛ID不会消耗未来展示；GameStart反复快照、迟到ID及转InProgress均不延长等待窗口。载入时显示成功后，进入游戏不再补弹；实际原生可见后才开始6秒收起倒计时。加载与对局阶段均可按住快捷键查看。对局ID尚未返回时的手动/按住操作也会消耗本次自动资格，不在ID迟到后补弹。展示资格按区服/比赛ID有界记忆，普通连接代际变化、同局刷新不重启。手动或按住操作优先于自动展示；前端计时条仅为视觉提示，真正6秒收起由Go截止时间控制，数据事件不能续期。

## 原生定位与输入

client_window_windows.go验证LeagueClientUx.exe的可见顶层窗口，只读取执行文件名、窗口边界、前台、最小化与DPI信息。WinEvent回调只通知单槽队列，不调用Wails/网络；连续通知合并35ms。赛前2秒兜底发现/核验窗口；加载/对局有自动展示资格或正在展示时2秒核验游戏前台，其余8秒或预览截止时检查。已无自动展示资格时不周期读取游戏前台进程。窗口移动不写盘、不查玩家。

定位取客户端可见框、当前显示器工作区与窗口DPI，使用物理像素；支持负坐标。左侧优先，右侧次之，空间判断以配置侧栏宽度为准；6逻辑像素装饰间距可按剩余空间缩到0。BUG-0058修正“宽度够但间距不够”误判：例如1920工作区中居中的1280客户端，两侧各320，默认320侧栏应在左侧贴边显示，收起重开也不能内覆。真正两侧都容不下完整宽度时才为28逻辑像素入口，显式展开从客户端左边向内覆盖。客户端最小化、隐藏、被切到其他应用时收起；侧栏自身接收输入时保持。自动显示不激活；只有显式恢复侧栏允许恢复客户端前台。侧栏和临时快览几何不覆盖手动快览保存尺寸，主窗口始终独立。

自动快览复用现有hold的非激活/鼠标穿透保护；失败保持隐藏并给出可用提示。初次辅助前端挂载完成才允许显示；创建前后核验阶段和前台。按住期间的松键、快速点按、焦点变化沿用internal/hold，不吞游戏原键。独占全屏与原生焦点仍须Windows实测，不能由浏览器合成验证保证。

## 数据与复盘

MatchRoom的当前资料直接使用Snapshot.participants，不依赖赛后review。房间/选人只显示实际我方，加载/游戏显示客户端已返回的双方；新房间/新比赛/进入加载默认当前，主动切到最近复盘后普通更新不抢回。首页当前状态入口也优先当前对局。打开当前卡片只读既有历史，不新取资料或分页；当前排位模式与侧栏/快览通过现有SetScoutQueue同步。最近复盘中的“赛前资料快照”是上一局归档，其模式/筛选只在该归档内生效。

侧栏与快览仅消费既有Snapshot/ScoutReport，SetScoutQueue只切缓存，辅助前端不初始化主应用工作区。英雄累计、12小时/30天/位置口径与SCOUTING一致，战绩列表筛选不改统计。

实际InProgress的本局名单持续更新内存候选；确认结算、返回房间/选人或同账号的None首页后深拷贝Participants及嵌套资料/报告，保存为最近一局MatchReview。结束时仍在加载的历史/统计转为已保留或未完整保留，不继续显示正在准备；复盘只读不解释为当前断线。断线、仅选人/载入、其他未知阶段不生成结束记录。新房间/新查询不修改已冻结资料，换核验账号清理隔离；不写玩家文件，不跨重启留存。复盘单双排/灵活切换与缓存战绩浏览是局部状态，不修改正在进行的侧栏/快览。

本局结果来自既有MatchDetailSource，并核验比赛ID；不能用赛前历史胜率/KDA代替结算。自动读取最多3次/15秒，每次含排队最多3秒，按约0/5/10秒尝试，部分结果继续补齐，共用串行调度且手动优先。断线、连接/账号变化、新游戏或退出取消，写回再次核验任务token、比赛与连接。正常回None首页不换连接、不取消本次同步；真实账号变化仍取消并隔离。单人3140训练结果不要求凑齐十人，团队占比仍只用于完整5v5。显式同步仍受原12秒手动门控，活动游戏不读取结算；失败保留已冻结资料并显示未同步，不持续轮询。

## 验证和交付

internal/companion纯测试覆盖定位、负坐标、折叠、一次展示与超时；engine回归覆盖深拷贝、退选/断线、账号与迟到结算隔离。Windows控制器/原生探针独立验证就绪、6秒、按住优先与焦点保护。

companion-browser使用合成桥接覆盖五人侧栏、英雄/模式/进度、窄入口、独立前端、1100/400快览、结算与赛前资料区别、新局与筛选隔离、880详情/七槽和统一设置；不证明Windows定位/焦点/计时真实运行。其他查询、首页、主题和组件回归继续运行。原生待验收见ACCEPTANCE。

不从Linux交付exe；Windows完整验证与候选仍使用干净dev提交上的 `bash scripts/build.sh`。

BUG-0056：载入时已开放自动/按住/手动快览资格；只改变窗口政策，不把InProgress首批资料查询提前。载入无完整敌方资料时展示实际名单和准备状态，不追加查询预算。

BUG-0055：选人未锁定同样展示已缓存英雄统计，活动pick可补当前预选；首轮逐人先返回第一页，不等所有熟练度完成，原预算不变。首页单场原位查看，双方详情保持显式按需；无赛前房间时不放失效展开按钮。首次物理快捷键按下复核游戏前台，失败在主窗展示，可导出不含身份/比赛ID/参数的阶段与就绪诊断。该补强仍需Windows实机验收。
