# R3 每次发版的固定回归

本清单覆盖首次启动、断线重连、客户端重启、热键冲突、WebView2 缺失和托盘退出。模板已准备，六项实机结果均为 **NOT_RUN**；自动化 CI 不代替本清单。R1 功能验收仍是本轮发版结论的前置条件，见[分轮清单](REAL_CLIENT_ACCEPTANCE.md)。

每个候选版本单独复制[空白结果表](acceptance/R3-results.csv)到本机该程序的证据目录，仓库只保留模板。记录测试日期、程序提交和 EXE SHA-256、Windows 构建号、客户端版本、窗口模式及 DPI；涉及安装器时补安装器 SHA-256 和 WebView2 版本。候选由 Windows 的受管构建入口生成，产物与记录规则见[ARTIFACTS.md](ARTIFACTS.md)。

## 六项固定步骤

| 编号 | 场景和步骤 | 通过标准 |
| --- | --- | --- |
| R3-01 | 在干净测试环境首次启动候选；先未连接客户端，再正常启动并登录客户端 | 未连接时展示连接指引；自动化默认关闭。连接后识别当前账号并展示逐步取得的资料；未知数据不补零，首次读取失败可显式重试 |
| R3-02 | 在无进行中对局时自然断开客户端连接，再正常恢复；已有战绩时同时观察旧资料 | 断线状态明确，已有资料可读且保留原更新时间；重连恢复当前账号，旧任务不覆盖新连接。记录未遇到的故障为 NOT_RUN |
| R3-03 | 助手保持运行，在客户端空闲时正常退出并重启游戏客户端；可用时另测换号 | 助手重新识别连接与阶段；名单、复盘、查询缓存按各自规则隔离；旧账号响应或自动化任务不写回新账号/新局。无法覆盖换号时单独注明范围 |
| R3-04 | 用测试环境中已占用的全局快捷键保存设置，再改成可用键；另核对配置的按住键、主窗和托盘备用入口 | 冲突提示可理解，失败不把草稿标为已同步，原生效配置仍有效；改键可保存。按住/松开不吞键、不抢焦点，备用入口可用。详细游戏中检查另按 S1 K1–K6 留存 |
| R3-05 | 在缺少 WebView2 的干净 Windows 10 环境，分别从安装器和 EXE 启动，再按引导安装运行库并重新启动 | 中文说明清楚，仅用户确认后打开微软固定页面；安装运行库后可启动。复用同一候选的 U3 I2 原始证据时注明编号与文件，不用有运行库的机器代替 |
| R3-06 | 打开主窗/侧栏或手动快览；先关闭主窗，再从托盘明确退出；随后重新启动助手 | 关闭主窗收起到托盘；托盘退出后助手及其窗口/监听正常结束，游戏客户端继续运行和接收输入；正常退出保存的窗口配置可恢复。退出卡住记 FAIL，不强制结束进程后填 PASS |

缺少适用环境或无法安全复现时填 BLOCKED / NOT_RUN，并写明条件。故障触发、输入与权限边界沿用[原验收说明](ACCEPTANCE.md)、[S1 按住快览](HOLD_INPUT.md)和[U3 安装](INSTALLATION.md)；连接/重启场景在客户端空闲时执行，缺运行库场景使用专用干净环境。

## 记录和结论

- 每行只用 PASS、FAIL、BLOCKED、NOT_RUN；失败写“操作 → 实际 → 预期”。同一编号出现失败时保留原记录，修复后的候选重新执行相关项。
- 每次发版保留六项记录和关联 R1 记录。复用同次验收的重叠步骤时引用原编号、环境、程序提交及证据；不同版本或缺失的步骤不推定通过。
- 六项全部 PASS 且本候选 R1 已完成，才能记录本轮 R3 通过。许可证/素材授权、平台规则、严格 TLS、签名、反作弊和整局性能仍分别按 Q8/R2/S9/U3/S1/F5 登记，不能由 R3 代替。
- 证据只保留必要的版本、状态和脱敏问题区域，不填玩家身份、鉴权、完整接口响应或输入流。上传/登记仍遵守[产物规则](ARTIFACTS.md)，不将空白表登记为已验收。
