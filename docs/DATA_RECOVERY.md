# 战绩服务降级与恢复（U2）

服务失败只影响对应的远端战绩，不清空账号、头像、段位、资料及已核验战绩。SGP不可用时优先返回已有LCU回退；若已有完整快照，有限的本机回退不覆盖它。失败时不更新`fetchedAt`，界面仍显示真实记录获取时间和“更新于N秒/分钟/小时前”。`HistoryMeta.service`和独立`checkedAt`表示本次服务检查结果；不能用最近的错误时间冒充数据已更新，也不能据此判断玩家隐私或没有历史。

SGP的内存冷却门按功能拆分为历史、排位、单场、组队四个独立通道（BUG-0084 P1-S2）：同通道内跨玩家、分页共享，通道之间互不等待；HTTP 请求不再持有共享锁，慢分页不会挡住段位或单场。不在锁或请求调度通道里睡眠，不创建来源轮询。401清掉对应的过期授权，下次允许读取时才获取新授权；不混用league-session与entitlements。只有服务明确拒绝才开门：401/403、429与5xx使用5/15/45/60秒递增等待，服务端合法Retry-After（秒或HTTP日期）要求更长时间时以服务端为准。BUG-0084起，可识别的本机超时与连接失败只让本次请求失败，不再冻结整批SGP读取；整轮截止、页数上限与页级一次重试是这类失败的上限。取消、格式/身份不匹配不自动重试。成功请求清冷却，连接/账号重置清会话状态；不持久化令牌、错误文本、响应、Retry-After原文或玩家标识。

冷却期间直接返回安全的错误码和允许重试的时间，不执行HTTP或刷新授权，也不把该等待记作网络请求。已有LCU回退仍可使用。手动刷新只能重读允许的资料，不能越过SGP等待时间；重试按钮在等待期间禁用。恢复成功清掉降级状态，保留模式与分析设置。自动行为和人工行为的边界如下。

| 场景 | 恢复方式与上限 |
| --- | --- |
| 可见的首页、完整玩家查询第一页，客户端处于空闲 | 等待到期后一次低优先级首批战绩读取；最多2次，整轮60秒，每次最多6秒；UI与Go双重上限，最多64个连接内玩家配额；不读取身份、资料、详情或扫描历史 |
| 同一显式分页/样本操作读取失败且没有可用回退页 | 等待在Go请求通道之外；同页最多2次重试，所有尝试计入原5/50页及15/90秒操作预算，不延长期限；失败不前移游标、不清记录 |
| 分页已返回有限LCU回退 | 立即展示该范围及原范围说明；不自动清掉已有页或跳回第一页重建，需要时显式刷新 |
| 原房间/选人准备、开局单轮、独立赛季统计 | 沿用原次数与期限；共享冷却避免绕过限流，本批不扩展其预算 |
| 局内、只读资料卡/冻结复盘、详情与时间线 | 不新增自动恢复请求；原授权的显式操作仍可使用 |

离开活动页、切玩家、隐藏页面、手动操作、断线/换号和阶段变化取消相关等待或请求；打开对局详情时暂停恢复，关闭后仅在剩余期限与配额内继续，避免刷新列表打断阅读。后台请求使用可抢占的automatic通道，等待不占通道，迟到结果复核连接及phaseEpoch。成功手动刷新结束旧失败轮次，可为未来独立故障建立新轮次。自动次数用完或服务要求等待超过期限时，明确提示等待/手动重试，不声称仍会自动恢复。

旧缓存先显后的后台更新有独立的、有界本地`leaguepingo:player-updated`事件。即使首页没有当前名单，也能收到恢复/降级结果。详情阅读期间暂存抵达的更新，关闭后应用，断线/换号丢弃旧连接的待应用数据。相同玩家的后台刷新合并，阶段/连接/退出取消，旧连接不向新账号发布；前端分别按fetchedAt和checkedAt合并记录与服务状态，旧状态不能复活已清除的故障。事件仅在本机Go与WebView之间传递当前界面原本可读取的玩家数据，不进入诊断或上传。降级页不写战绩磁盘缓存，会话状态和检查时间在存储净化时移除。

自动验证覆盖：退避及Retry-After、冷却跨玩家/路径且不重复取令牌、401重授权恢复、保留旧战绩/段位/时间、配额/手动优先/取消/换号迟到拒绝、后台首页事件、分页同页重试与原预算、成功清除故障、停止重试后的手动入口，以及880/1280布局与原五场可见密度。当前Linux运行逻辑/竞态、前端和portable，锁定Wails按Windows目标生成绑定；Windows全包及受管构建以本提交CI为准。国服真实断网/限流/授权恢复仍需人工验收。
