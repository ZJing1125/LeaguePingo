# R1 国服游戏电脑验收

当前状态：**部分项目已有用户实机反馈，R1尚未完成**。2026-10-30（北京时间）用户报告A1、A2、P1、P2没有问题，并指出赛后点赞页仍需手动处理。见[实机反馈记录](acceptance/R1-feedback.md)；实际运行提交、客户端版本等尚未补齐。开发环境只有Linux；Windows Actions只证明自动化检查与构建。下表是验收步骤，不是结果；空白CSV保持为可复用模板，不能据四项反馈登记整版已验收或宣称赛后全自动。

## 开始前

1. 在 Windows amd64 的干净 dev 工作区运行 `bash scripts/build.sh`，使用它登记的当前程序。已有构建机与游戏电脑分离时遵守 [环境和产物边界](ENVIRONMENTS.md)，当前没有自动下载部署流程。旧程序不包含本轮标注；不覆盖运行中的助手、不结束游戏进程。
2. 执行 `node scripts/artifacts.mjs audit`，记下 current 的 commit、sha256；在“设置与诊断 → 诊断与关于”核对运行程序提交。记录 Windows 版本、客户端版本、显示缩放和测试模式。构建成功、程序能打开均不代表后续项目通过。
3. 将 [空白结果表](acceptance/R1-results.csv) 复制到本机 `artifacts/<程序名去掉.exe>/r1-results.csv`。逐行填写实际测试日期、同一次程序提交和哈希、客户端版本、模式及观察结果。不同日期/客户端版本分行记录；保持未执行项为 `NOT_RUN`，受环境限制填 `BLOCKED`，与预期不符填 `FAIL`，确实完成该行全部检查才填 `PASS`。
4. 首先保持自动接受、自动返回、自动排队关闭；然后按对应项显式开启。每项测试结束恢复原设置。不要为了测试故意拒绝、挂机、制造限流或干扰真实玩家、系统网络与反作弊。

界面在自动化设置、攻略、已有同组标识和缓存/恢复入口标注“实验性”。此状态不会因 CI 通过而自动消失；分组缺失仍为未知，海克斯 2400 的分组展示仍未开放。

## 第一轮：普通使用与自动化

先做 A1–A4、P1–P5。通常需一次正常匹配和赛后流程；没有自然发生的场景留待后续，不为凑齐结果主动影响他人。

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| A1 | 打开设置，开启自动接受，选 1 秒延迟并保存；正常找到对局 | 本人状态及时变为已接受，主窗/侧栏同步；游戏保持前台，无模拟点击 |
| A2 | 主窗最小化、侧栏关闭，后台正在查战绩时正常找到对局 | 接受仍及时执行，不等待资料扫描；记录实际观察到的延迟 |
| A3 | 另一名玩家自然拒绝后再次找到对局，包括瞬时找到 | 每轮均能接受，没有因上一轮已接受而漏掉新一轮，也没有重复接受提示；未出现该场景记 NOT_RUN |
| A4 | 一次倒计时点“跳过本次”，及时手动接受；另一次关闭功能 | 本次助手不再接受、不发送拒绝；关闭后保持手动控制。已送达客户端的请求不能撤回 |
| P1 | 只打开自动返回；正常完成一局并完成需要手动操作的荣誉/奖励 | 先保留本局复盘，再返回房间；不自动投票/跳奖励、不开始排队；不支持的客户端阶段明确停止 |
| P2 | 两开关均开，单人或本人为队长，同模式正常结束 | 等房间允许开排后出现倒计时，并开始同模式排队；保留上一局复盘 |
| P3 | 本人为队员，队长保持控制 | 可返回，但不代队长开排；有人未回、邀请待定、房间不就绪时不抢跑 |
| P4 | 只打开自动排队；手动返回。倒计时中取消，或手动切模式/换成员 | 返回前不动作；取消/房间变化后停止旧任务，不再次替用户开排 |
| P5 | 自然发生重开，依次经过“继续”“再来一局”与房间 | 重开显示中性结果；保留复盘；不会把奖励页当房间提前搜索。记录实际是否需手动点继续；卡住或超时记录 FAIL，不写“保证自动化” |
| P6 | 只开“自动跳过点赞”，保持返回和排队关闭；正常结束有点赞页的比赛 | 3秒可取消，未选对象时自动结束点赞页，不替任何人点赞，不返回或开排；下局仍可执行 |
| P7 | 同时开跳过、返回与排队，在海克斯及普通模式核对“跳过→继续→再来一局→房间→开排”；另测倒计时手动选择/取消，以及关闭跳过 | 不要求旧点赞数据清空；已识别的进度页自动继续，再返回并开排；手动选择不被助手提交，完成后在原预算内继续；取消停止本次；关闭恢复原手动点赞。失败/未确认不重复提交，需手动处理，不伪称全自动 |

详细阶段/时间边界见 [自动接受](AUTO_ACCEPT.md)、[赛后动作](POST_GAME.md)、[跳过点赞](SKIP_HONOR.md)。P6/P7为新增能力，尚未获得国服结果；原P1/P2通过不推广到它们。真实流程无法稳定复现的超时/重复事件仍以合成回归单独记录，不能写为本表 PASS。

## 第二轮：双方分组与海克斯攻略

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| G1 | 对标准匹配模式双方十人，有**独立已知**的真实组队基准；在加载/局内执行下述匿名审计 | 同侧 20 个玩家对全部可比较，误合并/误拆分/未知均为 0；界面同组人数与基准相符 |
| G2 | 分别覆盖单双排、灵活 2+3 / 五排、普通匹配、普通大乱斗；另查缺字段和下一局 | 每种模式单独登记；缺失不作单排，新比赛不残留旧组。某一局成功不推广到全部模式 |
| G3 | 海克斯大乱斗 2400 | 只审计来源结构；尚未完成真实语义/双方基准前不展示同组标签。结构返回成功不能将该模式的组队识别记为 PASS |
| H1 | 海克斯 2400 选英雄/换英雄，打开主窗、侧栏和局内快览攻略 | 正确识别海克斯；强化品质/梯度/说明及出装与对应 OP.GG 原文相符；不套用普通 ARAM 或峡谷对位 |
| H2 | 手动选 3 个候选、搜索/品质筛选、跨窗查看，再换英雄 | 最多 3 个，跨窗同步；搜索/筛选不取数，换英雄清空。当前未实现自动识别游戏给出的 3 个候选 |
| H3 | 同英雄切换普通大乱斗、海克斯及当前可玩的其他模式 | 攻略/缓存按模式隔离，旧来源版本如实显示；未知模式明确不可用；局内快览不抢焦点 |

G1/G2 使用 [双方分组说明](PREMADE_GROUPS.md) 中匿名十槽位 JSON，基准必须来自测试组织者独立掌握的双方排队关系。不要用被测字段反向制作基准。敌方基准未知则记 BLOCKED，不用“看起来正确”代替；自定义房间不能代替匹配队列的语义验证。

```bash
bash scripts/audit-current-groups.sh --expected 本机匿名槽位基准.json
```

只在终端查看，不把完整审计输出重定向落盘或上传；结果表只填覆盖人数、20 对比较数、误合并/误拆分/未知等聚合数，不填身份、槽位关系或分组码。不会为本轮验收扩大自动读取或解匿名范围。

## 第三轮：缓存、恢复与退出

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| C1 | 空闲时查询玩家，第二次打开；正常退出再启动，重新连接核验同一身份 | 已有战绩先显示，原更新时间明确，后台刷新不阻塞手动查看；第一页与第二页右侧位置/参团/双方阵容一致；不逐行读详情 |
| C2 | 自然遇到数据服务不可用、授权过期或限流 | 账号/段位/旧战绩保留；失败不冒充刚更新，等待遵守限流。首页/查询首批每轮最多 2 次自动恢复；用完可手动重试；未遇故障记 NOT_RUN |
| C3 | 有待恢复任务时打开对局详情、切玩家/页面、进入游戏或换账号 | 阅读不中断；旧任务停止、迟到结果不覆盖新身份，局内不继续自动恢复；不为验收在游戏中强断连接 |
| X1 | 浅/深主题，880 主窗、280/320 侧栏及实际缩放；游戏前台按住快览键并松开 | 无遮挡或横向裁切，不吞键、不抢焦点，松开隐藏；侧栏不因外侧空间足够仍向内展开 |
| X2 | 本机导出脱敏诊断，正常从托盘退出 | 可导出固定聚合性能/请求/错误信息，无身份、凭据、原文或分组码；助手退出不影响客户端 |

C2 的真实 401/429/5xx 需要分别记录，不能为了触发它们大量请求国服服务。不可安全复现时保留未验证并使用已有合成故障结果作为独立补充。性能/FPS及反作弊兼容仍分别属于 F5/S1，本表不据一次顺畅操作宣称通过；完整历史场景见 [原验收清单](ACCEPTANCE.md)、[恢复边界](DATA_RECOVERY.md)。

## 反馈与结论

反馈最少包含：程序提交、客户端版本、日期、编号、PASS / FAIL / BLOCKED / NOT_RUN；失败再补“操作 → 实际显示 → 预期”。截图先遮住玩家名、标签、聊天等身份信息及同组标记，只保留问题区域；不提交真实资料、完整响应、授权或原始日志。

结果 CSV 与脱敏截图保留在本机对应程序证据目录。需要登记截图/CSV时使用现有 `node scripts/artifacts.mjs attach-evidence --file <当前程序路径> --apply`。只有用户明确验收通过后，才按 [产物规则](ARTIFACTS.md) 登记已验收状态；一项成功不代替全部 R1 项目。失败应定位修复并重新验收对应项，NOT_RUN/BLOCKED 继续保留待办。
