## 已采集的短基线

2026-10-16，Windows 本机、12 个逻辑处理器。生产编译、预热约四秒，再以一秒间隔采集 22 个样本，范围为助手主进程及可读后代（包括 WebView2），观察程序自身不计入。

| 场景 | 进程数 | 私有内存峰值 MiB | 工作集加总峰值 MiB | 平均 CPU（整机归一） |
| --- | ---: | ---: | ---: | ---: |
| 改造前：主窗口/快览均预创建且隐藏，无 LCU | 8 | 226.34 | 445.84 | 本次短采样未观察到可分辨增长 |
| 懒创建后：主窗口隐藏、快览未创建，无 LCU | 7 | 193.38 | 326.43 | 约 0.006% |
| 懒创建后：额外创建快览但保持隐藏，无 LCU | 8 | 219.20 | 394.80 | 本次短采样未观察到可分辨增长 |

第一组暴露了未使用快览仍预建 WebView 的常驻开销，因此改为首次打开时创建。此处每场景只有一次短测，不是统计学上的稳定优化幅度；第三组也不是游戏内打开快览的测量。

工作集包含共享页，加总可能重复计数，不能当作唯一占用的物理内存。CPU 接口有粒度限制，“未观察到增长”不表示零 CPU。采样遗漏短命进程，不能覆盖启动尖峰。私有内存约 193 MiB 的结果也说明当前原型不是零成本后台工具。Go 堆只是一部分，不可替代上述进程树数据。

原始 CSV 保留在本地 `bin/performance-batch6*`，不上传 Git。测试隔离实例使用单独应用标识和设置目录，不读取真实 LCU、不注册快捷键，35 秒自退出；没有终止现有助手或游戏。原生接口测试另验证 CPU 时间确实能观察到忙循环增长。

## 可复现工具

在 Git Bash 配好 Go 后：

```bash
# 启动隔离隐藏离线实例，并采集整个进程树
go run ./cmd/perfprobe -exe bin/leaguepingo-dev-20261016-v2.exe -out bin/performance-offline

# 包含已创建但保持隐藏的快览
go run ./cmd/perfprobe -exe bin/leaguepingo-dev-20261016-v2.exe -open-overlay -out bin/performance-overlay

# 对现有助手做只读采样，替换 12345 为实际助手 PID，不是游戏 PID
go run ./cmd/perfprobe -pid 12345 -seconds 120 -scenario champ-select -out bin/performance-pregame
```

工具使用 Windows 原生进程快照、CPU 时间和内存计数，不读取启动参数或进程内存内容，不抓包、不注入。程序不会停止原有进程。当前系统禁止执行 PowerShell 脚本，未更改或绕过该执行策略；因此使用原生 Go 工具，而不是修改系统安全设置。
