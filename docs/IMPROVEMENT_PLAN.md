## 数据定义（当前）

- 来源为当前连接的本地客户端，查询覆盖范围由客户端决定，不保证跨大区。
- 首次最多 20 场混合模式样本，用户可显式加载更多（最多 1000 条）；筛选和统计作用于已加载样本，不冒称某模式最近固定场次。
- 胜率分母仅为有确定胜负的记录；未知结果不视为失败。
- KDA 为完整 K/D/A 样本的总击杀加总助攻除以 `max(1, 总死亡)`；不采用逐场 KDA 平均值。
- 缺失为未知，真实零保留。仅显示客户端明确的提前结束信号，不冒称重开；隐私只认身份匹配的明确值，不由错误推断。
- 只核验目标身份可确认的记录；被排除记录计数及分类，避免隐形缩减样本。

## 验收边界

自动战绩预取在房间/排队/确认和选人进行，仅针对客户端提供的身份；局内保持手动查询与有限本地身份刷新。游戏前台、不同模式、跨屏/DPI和性能影响必须实际测量，不以浏览器模拟替代。

## 资料丰富度边界

Data Dragon 16.20.1 中文元数据和图标本地打包，173 位英雄及装备/召唤师技能；未知或版本外资源使用明确占位。终局装备、技能、时长、补刀、金币和英雄伤害只展示已返回的玩家摘要，不自动对 20 场逐个发起详情请求。常用英雄统计仍来自当前模式筛选后的有限样本。

等级、段位、隐私和真实头像属于可选能力，显式手动查询确认身份后在两秒额外预算内尝试，也可独立点击更新（三秒预算，不重查战绩）。失败不丢弃战绩，空响应不推断未定级；各字段保留上次成功时间，更新失败的旧值有标识。已加入身份匹配后的显式 PUBLIC/PRIVATE 解析、按需双方详情和分页；国服接口字段尚待实机核验。地图/位置/符文直接来自摘要，符文中文名称本地打包，不增加逐场请求。

## 准备策略

选人整次会话最多 45 秒，每位玩家最多两次尝试，英雄变更/失败不重置。房间使用独立预算，新增成员可延长准备机会但不重置已有成员尝试数；进入选人建立新预算。名称、身份搜索、分页、详情和资料请求共用串行调度，手动优先；相同连接/玩家在途历史合并。阶段检测与本地名单不被慢历史阻塞。

进入游戏后取消自动资料准备；名单不足时最多三次本地刷新，初期约两秒重试，完成或预算耗尽后恢复约二十秒阶段检查。单主题本地阶段通知会唤醒 HTTP 核验，并先取消非赛前阶段的准备；失败一分钟冷却，保留轮询。不承诺通知一定支持或即时到达，也不承诺赛前未知身份的战绩自动完成。

连接重新发现、注销阶段或赛前当前账号核验发现变化时使旧缓存与身份失效。无注销阶段的同连接换号已有合成回归，真实客户端流程仍需确认；局内不增加账号轮询。
