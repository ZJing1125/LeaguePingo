# 当前架构

LeaguePingo 是 Windows amd64 本地桌面助手，Go 负责客户端连接、读取、调度和原生窗口，Vue 负责已有数据的展示与显式操作。Wails v3 beta.29 连接两者；macOS 仅保留构建资源，尚无验收支持。工程目录见 [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)，历史方案见 [CHANGELOG](../CHANGELOG.md) 与 [BUGFIX_LOG](../BUGFIX_LOG.md)，本页只描述当前状态。

```text
Vue 3 / TypeScript
       │ Wails 绑定、快照与版本事件
       ▼
AppService ── Engine ── source.Source / 可选能力接口
       │          │               ├─ 本机 LCU HTTPS / 定向 WSS
       │          │               └─ 腾讯当前大区 SGP HTTPS
       │          └─ 请求调度、缓存、阶段准备、复盘与组队
       ├─ readycheck / postgame ── actionlane ── LCU 写动作
       └─ guides.Service ── OP.GG 官方 MCP / 固定公共页面

desktopApplication ── 主窗 / 托盘 / companion 辅助窗口
       └─ hold / 原生前台监控 / settings / diagnostics
```

## 职责与依赖

| 模块 | 当前职责 |
| --- | --- |
| `internal/core` | 可空业务模型、身份/战绩/时间线解析与纯统计；不依赖 UI |
| `internal/lcu` | lockfile/有限进程信息发现、固定回环 HTTP 和定向事件流；鉴权只在内存 |
| `internal/source` | 国服来源组合、SGP 会话/并发/冷却、身份核验与归一化；可选 Profile、Scout、分页、详情、时间线与分组能力 |
| `internal/engine` | 阶段编排、手动优先调度、准备任务、缓存及有序快照发布 |
| `internal/actionlane` | 用户开启的动作会话取消、换代失效、总时限及有界许可 |
| `internal/readycheck` / `postgame` | 各自业务状态机和动作前后客户端核验；不合并为通用自动点击器 |
| `internal/guides` | 公共模式/英雄攻略、内容归一化、限时任务和公共缓存 |
| `internal/companion` / `hold` | 窗口资格与贴靠、按住输入门控；不读取玩家资料 |
| `internal/apperrors` / `diagnostics` | 固定中文错误码、脱敏聚合与本机显式导出 |
| `frontend/src` | 概览、战绩、资料、对局和辅助设置；按身份与独立时间合并已有结果 |

`main()` 只做 WebView2 前置检查、创建生命周期、传入资源和运行。`desktopApplication` 显式持有桥接、窗口、监控和取消依赖；`desktop_app` 负责组装/托盘/关闭，`desktop_controls` 负责侧栏与设置，`desktop_workers` 负责事件转发和启动任务。单实例检查早于服务创建，重复启动只唤起已有实例；关闭时先取消工作，再停监控和保存设置。

Engine的独立锁组件包括：`eventSubscription`管理事件取消/序号/重连与唤醒，`groupingState`持有分组scope/匿名字段/标签与单轮取消，`reviewState`持有候选/冻结复盘/归属账号与结算令牌。复盘视图发布后只读，更新替换外层值；锁顺序固定Engine→组件，Watch、来源I/O、引擎发布和通知回调均在组件锁外。Engine仍核验连接/阶段/英雄epoch、当前身份及比赛，字段由59经51、45降为41；缓存、准备、查询等尚未全部拆分，S2仍进行中。

## 阶段与并发

内部使用 `Stage` / `Phase` 与集中行为表，对外 Snapshot 保留原字符串。未知 Phase 按 idle 展示，未知 Stage 失败关闭。每次连接/账号变化递增版本、取消旧任务并隔离旧缓存；阶段、订阅和任务各有独立序号，排队前、取调度槽后和写回前拒绝迟到结果。

| 场景 | 读取与展示 |
| --- | --- |
| 未连接 | 保留旧资料并标旧；首页提供三步连接指引，不自动查玩家 |
| 空闲 | 当前账号首批资料每连接/账号准备一次，最多 12 秒；前端失败不靠重复快照重启 |
| 房间/排队/接受/选人 | 准备实际可见身份，历史优先、可选资料随后；选人事件合并唤醒，轮询仍作兜底 |
| 加载/局内 | 有界刷新本地名单，正式开局/局内启动只补齐缺失资料一轮；不持续自动扫描玩家 |
| 结算 | 冻结本次运行最近一局；完整结果允许最多 3 次/15 秒有界同步，非游戏阶段才读详情 |

阶段流每连接至多一条；选人流只在选人阶段存在。失败后同连接一分钟再试，事件与轮询共用阶段核验，不订阅全量账号/战绩事件。阶段内容、玩家身份和事件正文不进入诊断。

玩家任务经 `requestScheduler` 串行执行，手动操作可取消低优先级自动读取并取得优先权；本机阶段/名单探测不被慢历史请求阻塞。来源层的历史/段位/详情/组队各最多 4 个远端在途请求，等待可取消且计入原预算；这不是引擎自动扩大并行查询许可。

准备首批历史与完整独立统计是两条任务：首批房间/选人与开局各沿用 10 人/45 秒边界；独立 Scout 按[SCOUTING.md](SCOUTING.md)的 180 秒、500 页合计预算逐人发布。12 小时/30 天/当前赛季范围不从列表“最近 N 场”推算。渲染、换主题、悬停、换英雄、快览显隐不重启准备。

## 来源与失败处理

身份仅接受当前客户端核验的 PUUID，姓名清理不改变有效内部字符。LCU 别名查询使用结构化名称/标签并核验唯一结果；名单不完整不伪造对手，不从姓名反推身份或从查询失败推断隐私。

历史首页和后续页统一优先 SGP SUMMARY，SGP 不可用时首页可回退 LCU；LCU 偏移不可靠，回退范围上限不表示账号历史终点。段位优先 SGP rankedStats，使用 league-session；SUMMARY 使用 entitlements，两类令牌独立合并/短缓存并在换号清除。SGP 只接受客户端当前大区匹配的固定腾讯 HTTPS 地址，正常证书校验、禁重定向/代理、8 MiB 响应上限。LCU 固定本机回环，目前仍使用自签名兼容传输；严格根证书验证属于尚未完成的 S9，不能宣称已实施。

SGP 认证/限流/服务错误进入共享冷却：5/15/45/60 秒基线加 0–20% 非负抖动，本机上限 60 秒，服务端更长 Retry-After 优先。并行迟到成功不能清除较新的冷却，重叠拒绝不能缩短等待。无内部无限重试；有限恢复和旧资料策略见 [DATA_RECOVERY.md](DATA_RECOVERY.md)。错误只按固定目录展示，协议见 [ERRORS.md](ERRORS.md)。

详情与时间线校验比赛和参与者，不从摘要反推过程。打开单场详情即授权读取双方记分板；时间线/出装过程仍需显式读取。只有完整标准 5v5 且字段齐全才计算团队占比；缺失显示未知，明确零保留，重开不计作失败。数据来源对照工具仅在显式测试中编译启用，见 [PLAYER_DATA_AUDIT.md](PLAYER_DATA_AUDIT.md)。

## 缓存与数据边界

- Participant/Profile/Scout 以内存时效复用，各字段保留自己的成功时间和本次状态；失败不刷新旧值时间，不把缺失负场补零。完整 ID/已选玩家的过期已核验历史立即显示，复用合并的 12 秒低优先级刷新；显式强制刷新仍同步执行。
- `history-cache.json` schema 3 最多 8 MiB、64 身份/每人 50 页；仅保存去姓名的 HistoryPage 摘要和匿名英雄阵容。身份索引使用独立 0600 本机随机密钥的 HMAC-SHA256；不含原 PUUID、Riot ID、姓名、授权、Profile、Scout、详情、时间线或原始响应。重启必须重新核验身份才命中，旧 schema/坏文件/坏密钥在本轮重建。
- 持久化对深拷贝快照在锁外编码；临时文件写入、同步、关闭及最多 3 次 Rename，任一步失败只计固定诊断并保留可用内存。身份更新时淘汰旧偏移，避免新增比赛后的页错位。
- SGP 内存页为 512 页/15 秒 TTL LRU，64 个玩家首页游标单独淘汰；首页变化只失效该玩家页，并拒绝旧在途分页回填。授权和 HTTP 不在缓存锁内进行。
- OP.GG 缓存只包含公共英雄攻略；请求仅包含模式、英雄、分路、对位和语言，不发送玩家/房间/对局身份或 LCU 授权。内容任务 8 秒、HTTP 5 秒、失败冷却 30 秒；关闭攻略会取消在途读取。来源、模式兼容、7 天缓存和版本参考见 [HERO_GUIDES.md](HERO_GUIDES.md)。
- 设置只保存本机非敏感偏好；主题在 WebView 本机存储。诊断无自动遥测/上传，只显式导出固定聚合；导出报告由用户手动管理，不后台轮转删除。分组码只在内存，不写缓存、设置或报告。

## 前端与窗口

首页只按 Snapshot.selfKey 展示已核验当前账号，查询标签与当前对局独立。筛选的最近 N 场、每页 20 场和独立累计统计是不同口径：按需扫描的样本最多 1000 条混合记录/90 秒，远页跳转每轮最多 5 页/15 秒，可停止、缓存复用且不阻塞搜索/详情。常用英雄在左列、熟练度上方；首页战绩自然增高。快照与详情按连接编号和各自时钟合并，不污染另一个玩家或工作区。

主窗对局室分别展示当前资料与最近复盘，新房间不覆盖上一局归档。辅助侧栏与局内快览共用一个懒创建 WebView；贴靠优先客户端左侧外部，再选右侧，间距可缩到零，两侧不足才窄入口/显式内覆，不移动客户端。加载/开局具备资格且游戏前台、名单可展示时自动一次 6 秒；重连不补弹。窗口政策见 [COMPANION.md](COMPANION.md)。

按住快览仅处理已配置键，回调只原子更新并投递单槽信号；前台查询在工作任务执行，始终传递原按键。临时窗口非激活/鼠标穿透，保护失败不显示；手动窗口可交互。主窗/托盘不依赖全局热键，原生焦点、DPI 与反作弊仍需游戏电脑验收，见 [HOLD_INPUT.md](HOLD_INPUT.md)。

自动接受、跳过点赞、返回和排队均默认关闭，唯一设置入口为游戏辅助页，可一键停用。动作前复核客户端状态，写后读核验，不模拟输入、不替用户选英雄/奖励/点赞对象，不因错误盲目重发；每轮取消持久跳过。细则见 [AUTO_ACCEPT.md](AUTO_ACCEPT.md)、[SKIP_HONOR.md](SKIP_HONOR.md) 与 [POST_GAME.md](POST_GAME.md)。
