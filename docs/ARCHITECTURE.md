# 架构与技术选型

## 模块

```text
Vue 3 + TypeScript UI
        │ Wails 绑定 / 快照事件
        ▼
AppService ── Engine（阶段机、单路预取、内存快照）
                    │ Source 接口
                    ▼
              TencentLCU 适配层
                    │ 仅 127.0.0.1 HTTPS GET
                    ▼
              League Client API
```

- `internal/core`：不依赖 UI 或客户端的模型、选人名单和战绩解析、样本统计。
- `internal/source`：数据源接口及腾讯国服 LCU 适配层。将来 Riot 国际服可以增加另一实现，而不改引擎或前端模型；国际服可能需要 Riot API 凭据、地区路由和另一套身份解析。
- Riot 官方 API 本身不保证提供选人阶段十人名单；国际服若要保留赛前自动准备能力，预计仍需将本地客户端可见身份与官方战绩 API 组合，不能只替换一条远程 URL。
- `internal/lcu`：发现 `LeagueClient.exe`、读取 lockfile、只允许连接本机回环地址的只读 HTTP 客户端。
- `internal/engine`：轮询阶段、管理查询取消与代际快照、冻结正式对局数据。选人阶段约 3 秒检查阶段；正式对局约 20 秒检查阶段，仅获取阶段，不发起自动历史战绩查询。
- Wails 主程序：主窗口加预创建的隐藏快览窗口；全局快捷键负责显隐，快览窗口设为置顶且鼠标穿透，避免抢占游戏操作。

## 关键状态

| 阶段 | 自动动作 | 查询范围 |
| --- | --- | --- |
| 未连接 / 大厅 / 排队 / 接受确认 | 低频检查客户端阶段 | 手动完整 Riot ID 查询（客户端连接后） |
| 选人 | 读取名单，已知身份玩家串行查询，未知身份保留占位 | 仅客户端提供有效 PUUID 的玩家 |
| 正式对局 | 冻结已有内存快照，快捷键按需显示 | 不发起新的历史战绩查询 |
| 回到大厅 | 清空本局快照 | 恢复手动查询 |

名单若临时缺失，保留上一份选人快照；名单变动时按 PUUID 继承已完成的数据。快照通过有界、有序的事件队列推送给 UI，慢速前端不会阻塞阶段检测。

## 技术权衡

Wails + Go 便于编写本机客户端适配和低资源后台逻辑，Vue 3 + TypeScript 便于迭代界面。Wails 3 目前仍是 beta；采用它是为了多窗口、全局快捷键和鼠标穿透能力，但这些行为仍需 Windows 和游戏环境实测。若 beta 稳定性不足，迁移到稳定桌面框架可能成为发布前任务。

没有把客户端 API 查询失败推断为“生涯不公开”。也没有声称选人阶段一定可以获得双方十人身份；可见身份随模式、客户端版本和匿名化策略变化。
