# 架构与技术选型

## BUG-0065：纯本地战绩快照与前后台调度

首批LCU历史仍是可见结果的起点；前端不等网络才允许浏览。首页和完整战绩页在空闲1.2秒后用同一个混合历史游标低优先级准备单双排与灵活排位，扫描直到各自达到所选10–50场、来源耗尽/受限、最近1000条或90秒边界。所选模式“最近N场”的精确定义不变，预热只是把原来切换后的工作提前，不能用首批混合20场替代。

HistoryPage不再占用全局手动操作门控。页面先查本地快照：五分钟内直接返回；过期页立即返回并静默刷新；缺页进入自动请求通道。requestScheduler记录当前可取消的自动请求，搜索、刷新、资料、单场详情等手动操作排队时取消它并取得优先级；被中断任务不写入迟到结果，前端保留已读游标，后续激活或显式继续可恢复。模式/样本选择立即更新本地计算，后台状态不禁用筛选、搜索和已有详情。

`history-cache.json`位于应用配置目录，schema固定、原子替换、权限0600，最多64个身份、每身份50页。键仅为SHA-256(PUUID)，页面写入前移除阵容，因此文件不含原PUUID、Riot ID、玩家名、授权、Profile、Scout、详情、时间线或原始响应。每页按自身fetchedAt判断时效，刷新另一页不会延长旧页；检测到新的历史首页时清除旧偏移页，避免比赛新增后分页错位。进程重启后必须由当前客户端重新提供并核验PUUID，才把哈希命中的摘要绑定到新connectionId；坏文件只禁用本轮磁盘缓存，不阻止程序运行。该设计没有服务端或账号同步。

## BUG-0060：来源对照与验证边界

显式数据核验只编译在source测试中，不进产品桥接或自动调度。Windows入口在账号/阶段稳定时串行执行两源段位、原始偏移分页、同局双源记分板/时间线，最多45秒/3页/一局，输出固定JSON计数/差异/覆盖；无身份、比赛ID、正文或原始错误。source级合成测试核对界限、阶段中止、空/零差异、报告脱敏和真实端点契约；完整统计/UI/国服数据仍各自验收。生产唯一取数修正为同响应双队列容器合并时保留明确历史字段，无新运行时依赖、模型或接口。见PLAYER_DATA_AUDIT。

## BUG-0059：已读分析与显式时间线

Match新增等级/承伤/视野/守卫/连杀/属性碎片、可核验参团及无PUUID的紧凑阵容；LCU嵌套与SGP扁平SUMMARY共用归一化与身份核验。MatchDetail保留mapId及真实队伍资源目标。没有为战绩行添加请求。Profile保留最高/上季段位，熟练度仅在既有串行资料任务/父预算剩余时间内用300ms补读一次，与独立Scout共享5分钟/64身份缓存，换账号清除；失败不改已保存字段时效。

新增可选MatchTimelineSource与桥接MatchTimeline。用户明确读取后，在同一12秒手动门控/串行调度中复用已核验详情或按需取得详情，再取时间线；最多8局/5分钟，仅内存、连接失效清理，拒绝迟到写回。返回同时带核验详情，出装标签不再二次请求。LCU路径为 /lol-match-history/v1/game-timelines/{gameId}；本地请求失败才可用既有HTTPS官方源/entitlements访问 /match-history-query/v1/products/lol/{platform}_{gameId}/DETAILS。详情SUMMARY采用相同回退规则；本地成功但格式/比赛或身份不匹配直接失败，不掩盖异常。授权继续与排位league-session分开，固定sgp-detail/sgp-timeline诊断不记身份或原始响应。

解析只接收核验比赛与参与者，限制8MiB、720帧、20000相关事件、12小时范围；严格帧顺序与参与者ID，SGP还核对platform/game/target。保留空字段，只有实际记录才能生成事件/位置/经济曲线；不反推比赛过程。团队总量只在完整5v5且该字段齐全时提供。渲染、标签、翻页、侧栏/快览和游戏阶段准备不调用新来源，原Scout与首批资料预算不变。


## BUG-0058：侧栏外侧空间与间距

internal/companion.Place仍只接受物理像素边界，缩放换算由现有controller负责。左右余量达到侧栏配置宽度就视为可停靠，不把6逻辑像素装饰间距算作硬门槛；选左优先，间距取配置值与该侧剩余空白的较小值。宽度、同高、工作区钳位、负坐标支持以及真正不足时的窄入口/显式内覆保持原策略。

1920工作区/居中1280客户端/320侧栏的旧行为可复现：左右各320却要求326，自动变窄入口，显式展开X=320与客户端重叠；现在X=0、宽320，刚好停在客户端左边。纯策略回归覆盖自动/重开及缩放边界；控制器回归覆盖侧栏收起与主程序切换两条入口。无窗口API、前端、绑定、玩家请求或设置格式变化，Windows实际贴靠仍待实机核对。


## BUG-0056：加载快览与排位胜负可信度

窗口资格统一由companion.InGame定义：已连接的GameStart或InProgress。原生自动显示、前台探测、按住Allow与手动入口共同使用；数据准备仍等InProgress，不能全局替换引擎的阶段门槛。从首次加载（直接局内启动为首次InProgress）起45秒等待，实际显示后6秒，转阶段不续期；无ID重连的抑制保持到迟到ID出现，防止多次快照漏掉重连标记。窗口始终复用同一个WebView。

排位取数以BUG-0057为准，替代原非本人零负场置空及无条件优先逐场统计的处理。

## BUG-0057：查询页排位统计通道

TencentLCU的统一Profile/Ranks在已有调度任务内优先请求当前大区SGP `/leagues-ledge/v2/rankedStats/puuid/{puuid}`。授权来自 `/lol-league-session/v1/league-session-token` 的JSON字符串；不能使用SUMMARY的entitlements。两类会话共用已核验官方HTTPS源和拒绝重定向的传输，token各自内存缓存两分钟、各自401/403清除；账号重置清除全部。新诊断只用固定sgp-rank/rank-session类别，不保存身份或授权。

远端请求限1.2秒且不超过父资料剩余时间的一半，仍包含在原每人3秒/手动12秒总预算内。SGP两队列齐全不再读LCU；缺队列或失败回退既有LCU，只选择整条队列，不拼跨来源的胜负、段位和赛季。Rank增加可选source/seasonId；SGP小段是rank，LCU是division。双容器缺失字段可同源补齐，冲突队列不由顺序裁决。解析保留明确零值，不凭本人/他人身份修改负场。

rankRecord有完整SGP胜负时直接用于首页/资料头/侧栏展开/快览，范围为排位；独立ScoutReport仅在聚合胜负缺失时提供明确的本季/本季已读范围，之后才回退LCU完整胜负。筛选列表不参与任何排位卡总数。12小时/30天和英雄表现仍用独立报告，预算与范围不变。

用户报告e9a9a1f中查询页两张段位卡均0负场；该版本缺失值显示—，不会由前端补0，且只接LCU段位来源。SGP是已实现的候选修正通道，当前Linux无用户客户端，尚未观察其真实返回，不能宣称已证实LCU受限或SGP必然恢复；显式单玩家对照见ACCEPTANCE。

## BUG-0055：准备时机、结算延迟与详情

ScoutSource调用数与180秒/500页/十人预算不变；首轮改为每个人的熟练度后立即读取其第一页，再处理下一人，避免所有熟练度形成首批数据屏障。活动pick动作只补我方未确认英雄；UI不以锁定状态限制ScoutReport。

None是客户端正常首页。阶段轮询仍核验当前账号，只有实际账号改变/连接失效才换代并重置来源身份；正常赛后None保持结算任务。实际游戏已留候选且同一核验账号的None也可冻结赛后记录。结算仍至多三次、总15秒、每次含调度3秒，按0/5/10秒就绪窗口尝试，部分返回不提前结束；新游戏/换号/断线/退出与token拒绝迟到写入保持。仅已核验本人的单人3140训练返回可标为同步完成，团队占比仍遵循完整5v5，不伪造其他参与者。

快捷键首个物理按下重新核验前台进程，自动展示前在载入期预热WebView（BUG-0056起载入就绪可显示）；OverlayStatus的原生失败信息可见于主窗口，显式脱敏诊断记录阶段/人数/前端就绪/最近前台检测/窗口与快捷键状态，不含姓名、比赛ID、进程参数或接口正文。Linux目标编译和合成UI不能证明游戏内原生可见。

## BUG-0054 辅助窗口与复盘补充

当前窗口/复盘分工以 [COMPANION.md](COMPANION.md) 为准，替代下文旧实时主对局室入口与只手动读取整场详情的描述。新增internal/companion只计算阶段/展示资格/左优先定位；主程序复用一个辅助WebView，原生WinEvent合并35ms通知，赛前2秒兜底，其余8秒或预览截止时间；窗口路径不调用数据源。internal/engine/match_review.go在实际InProgress保留候选，确认结束/回房间后深拷贝，Snapshot.review保留最近一局；断线、载入取消与未知阶段不当作结束。赛后例外复用MatchDetailSource，最多3次/15秒、单次3秒，手动优先，连接/账号/对局及任务token隔离，活动游戏停止。其他历史/资料/独立统计预算保持原值。


BUG-0050：新增独立 ScoutSource/ScoutReport，英雄当前赛季与12小时/30天统计不与列表样本共用；范围、调度、缓存和完整性定义以 SCOUTING.md 为准，替代下文旧“仅近20场对局统计”和“不自动分页”对本通道的限制。Snapshot.queueId 为已读会话队列，scoutQueue 为统一展示选择；SetScoutQueue 仅更新快照。其余历史、资料、首页与原生快览规则继续适用。

## 模块

BUG-0048 新增 Snapshot.selfKey，来源为已验证的当前账号；局内只使用本地名单读取时已取得的身份缓存，不为首页新增局内账号请求。空闲阶段复用原低频轮询检查同客户端换号。CurrentPlayer 只面向本人，校验连接编号，缓存优先；只允许在 idle 准备一次首批历史和可选资料，复用原手动门控、串行调度与 12 秒上限。离开 idle/断线/换号/退出取消，迟到结果不得覆盖新阶段缓存。房间、选人和游戏阶段只返回现有准备结果，由原有任务负责补齐。前端每连接/账号自动尝试一次，失败不轮询，显式刷新走原 RefreshData。

首页状态独立于查询标签；仅按 selfKey/connectionId 合并名单与首页的历史/资料时钟，不能从排序或最近查询推断当前账号。外观只在本机 WebView 存储 light/dark/system 选择，响应系统外观和存储事件；无新增依赖、玩家持久化或主题网络请求。原生窗口、对局预算与快览焦点规则保持原边界。

```text
Vue 3 + TypeScript UI
        │ Wails 绑定 / 快照事件
        ▼
AppService ── Engine（阶段机、单路预取、手动查询门控、内存快照）
                    │ Source 接口
                    ▼
              TencentLCU 适配层
                    ├─ 127.0.0.1 HTTPS 读取 / 阶段及选人定向 WSS
                    │       └─ League Client API（身份、首批历史、阶段）
                    └─ 显式 HTTPS 分页
                            └─ 腾讯当前大区 SGP（后续历史）
```

- `internal/core`：不依赖 UI 或客户端的模型、选人名单和战绩解析、样本统计。
- `internal/source`：数据源接口及腾讯国服 LCU 适配层。选人阶段由可选 ChampSelectSource 直接读取 champ-select，会话中的 myTeam/theirTeam 为双方；正式对局 gameflow 优先，必要时回退选人名单。缓存当前连接的自账号 PUUID，按实际所在阵营排列我方/对方，不假设 `teamOne` 就是我方。名单自带名称直接展示，不为局内自动刷新额外请求玩家资料。将来 Riot 国际服可以增加另一实现，而不改引擎或前端模型；国际服可能需要 Riot API 凭据、地区路由和另一套身份解析。
- Riot 官方 API 本身不保证提供选人阶段十人名单；国际服若要保留赛前自动准备能力，预计仍需将本地客户端可见身份与官方战绩 API 组合，不能只替换一条远程 URL。
- `internal/lcu`：发现 `LeagueClient.exe` / `LeagueClientUx.exe`，优先读取有效 lockfile；不可用时仅以有限查询权限获取客户端启动参数，不读取游戏内存。鉴权信息仅存于内存，失败原因脱敏后传给引擎；HTTP 请求固定使用本机回环地址并禁用代理。WSS 定向订阅 gameflow-phase（16 KiB 上限）和仅选人阶段的 champ-select/session（256 KiB 上限），固定回环地址、不跟随重定向，不订阅账号/战绩等全量事件。选人事件只保留内存签名用于去重，不持久保存或转发正文。
- `internal/engine`：轮询阶段、管理查询取消与代际快照。选人阶段约 3 秒检查阶段并串行预取；正式开局仅为缺失资料补齐一轮，之后约 20 秒检查阶段，不持续自动查历史。可选阶段通知唤醒核验；非赛前通知先取消准备，通知前在途的旧阶段响应不能恢复准备。订阅失败同连接一分钟冷却，轮询仍可独立工作。入局时对本地名单有限刷新；用户手动查询另有共享门控和 12 秒超时。
- Wails 主程序：以固定应用标识实施单实例，重复启动通知已有主窗口，不创建新的查询引擎或托盘。快览在首次请求显示时才创建 WebView；之后隐藏保留以便再打开。未使用快览时不预建第二个 WebView。
- `desktop_window.go`：主窗口无边框及浅色原生主题，保留默认可缩放和系统装饰。`DesktopTitleBar.vue` 使用 Wails beta.29 的 Window 运行时管理最小化、最大化／还原和 Close；Close 仍经过主程序的隐藏到托盘钩子。原生窗口状态事件与初始化查询隔离迟到结果，不定时轮询、不增加业务请求。托盘唤起也执行 UnMinimise。
- `overlay.go`：在 UI 线程串行管理快览懒创建、显隐和置顶，通过递增版本事件同步两窗口。手动快览保持接收鼠标操作，有原生拖动区、关闭入口和获焦 Esc 隐藏；临时按住模式单独使用非激活和鼠标穿透，松键不关闭手动模式。默认 `Ctrl+Shift+P`，允许在设置中改为 Ctrl+Shift+A–Z；冲突失败不替换旧注册。
- `internal/hold`：独立按键状态机；Windows 自有消息线程使用 WH_KEYBOARD_LL 和 EVENT_SYSTEM_FOREGROUND，不吞键、不注入游戏。键盘回调只更新状态并通知有界单槽队列；只有按住期间使用 150ms 的松键/焦点恢复检查，空闲无按键轮询。前台进程仅用有限查询权限核对执行文件 basename，不读取参数或游戏内存。引擎快照仅提供连接/阶段门控，不发数据请求。
- `overlay_native_windows.go`：通过 Wails beta.29 公共 NativeWindow 获取 HWND。隐藏创建后临时设置 WS_EX_NOACTIVATE、分层/鼠标穿透，线程内 CBT 钩子拒绝该窗口在 Wails Show 时被激活；保护失败则不显示。临时模式居于游戏显示器工作区，UI 控制器在初始化前后复查物理状态；隐藏时恢复样式、交互和手动几何。原生焦点、DPI 和独占全屏兼容尚需 Windows 验收。无需新增业务查询预算。
- `internal/settings`：版本化非敏感 JSON，临时文件写入后替换；窗口拖动只更新内存，明确设置操作和正常退出才写盘。恢复时按当前显示器工作区约束窗口，允许负坐标副屏，不持久保存 ID/历史。
- `internal/diagnostics`：仅汇总固定类别的请求计数/耗时/失败/状态码，始终不保存 URL 参数、鉴权、响应或原始错误。AppService 显式本地导出，没有遥测上传。界面 Go 堆值明确不代表总进程内存。
- 前端：玩家战绩和当前对局独立工作区，最多八个内存标签及每玩家筛选/展开状态；历史与资料分别择新，错误按连接/玩家归属，阶段变化不清掉显式查询结果。共享纸白/墨色/橙色 tokens、本地原画及 SVG、默认装备/技能与上下两排阵容的规范见 UI_DESIGN.md。静态中文资源和雪碧图随程序打包，不在局内访问 CDN。
- 前端组织：快照择新、玩家工作区、手动操作与快览控制分别抽入 composable；App 组合事件与界面。资料头部和战绩行是无 Wails 依赖的展示组件，详情由父层插槽接入。独立 Histoire 工具链只用于合成预览，不进入生产构建、不增加客户端请求；见 FRONTEND_GUIDE.md。

## 关键状态

选人通知只比较 gameId、双方位置/身份、championId/championPickIntent，计时等无关字段不触发读取。通知经单槽队列/250 ms 窗口合并，由主循环串行核验 Phase 和选人会话，事件读取不复查账号/资料；普通轮询仍每轮完成后等待 3 秒。版本、订阅序号、阶段和英雄事件 epoch 隔离迟到结果；非选人通知立即取消选人订阅。订阅故障一分钟冷却，未送达事件由轮询补足，不承诺捕获每一个瞬间操作。只更新英雄不会重置已有准备预算或重拉已就绪历史。

Participant 的 championState 区分 selected/intent/unselected/unavailable；缺失英雄信息不等同于未选择，预选不覆盖已有确认英雄。前端 ParticipantAvatar 在本地英雄资源、已有账号头像和人物图标间回退，组件本身不新增请求。用户打开资料的补取另走 EnsureProfile，不由英雄/名单事件驱动。临时错误按操作键管理 2 秒定时器，统一 TransientNotice 在 150 ms 渐入、2 秒到期后 200 ms 渐出并收起网格高度；重复错误重置，切换玩家不串入旧错误，减少动态效果时停用动画；持续连接/配置告警仍常显。

| 阶段 | 自动动作 | 查询范围 |
| --- | --- | --- |
| 未连接 | 低频发现客户端 | 已有离线资料 |
| 大厅 / 排队 / 接受确认 | 约 6 秒检查阶段与房间成员，串行准备已知身份 | 仅房间已知成员；不构造对手 |
| 选人 | 读取名单，已知身份玩家串行查询，未知身份保留占位 | 仅客户端提供有效 PUUID 的玩家 |
| 正式对局 / 重连 | 有限刷新本地身份，正常开局或局内启动均只补齐缺失资料一轮；同局重连不重启 | 允许显式查询完整 ID / 所选玩家，也可手动刷新名单 |
| 观战 / 结算 | 保留已有快照，不自动补全名单或战绩 | 可查看缓存，完整 ID 手动查询仍可用 |
| 回到大厅 | 替换为当前房间成员，本局 ID 清零 | 房间已知成员与完整 ID 查询 |

名单若临时缺失，保留缓存；同局名单变动时按 PUUID 继承已完成的数据，已知对局 ID 发生变化时不继承上一局战绩。快照通过有界、有序的事件队列推送给 UI，慢速前端不会阻塞阶段检测。连接发现失败时发布可读原因，局内断线保留缓存。

## 局内请求边界

- `Frozen` 表示停止持续自动战绩预取，不禁止快照更新或用户操作。赛前入局时取消旧准备。BUG-0043 根据用户开局对手反馈，将 BUG-0042 的冷启动例外扩展为每局开局一轮缺失资料补齐。
- `initial_match.go` 的任务归 Engine.Run 生命周期管理；GameStart 等到正式对局再执行。等待本地身份的有界刷新，绑定连接/对局 ID，最多 10 个有效身份、总计 45 秒，每人至多一次缺失姓名和一次 LCU 首批战绩；先完成首批历史，再用同轮剩余预算补头像/等级/段位；不取 SGP 后续页或整场详情。共享单路调度，手动操作优先；复用赛前新鲜缓存和在途请求，已取消的赛前历史任务不能代替本轮实际请求。阶段离局、连接变化、关闭或超时取消；同局轮询、手动刷新和重连不重启，新局按新对局 ID 独立计次。完成回调校验任务 token，上一局迟到结束不能取消新局任务。停止后清理 loading，缺失项保留手动入口。
- 名单解析接受客户端已提供的 gameName/tagLine、riotIdGameName/riotIdTagLine 和旧名称；姓名端点必须匹配目标 PUUID，未知身份不据姓名反推。姓名与历史时间独立合并；手动查询命中缓存、刷新战绩或打开资料时仍可补取缺失姓名，并只更新同连接的姓名字段，保留并发完成的历史/资料。已有姓名不重复请求；来源未提供时不冒称仍在加载。
- 入局或局中首次启动时 GameStart 最多进行三次逻辑名单刷新；若仍不完整，载入期间每 5 秒只查阶段，转为 InProgress 后最多再进行三次本地名单刷新，取得完整十人名单及非零对局 ID 后停止。一次逻辑刷新可能包含 gameflow、自账号首次识别和不完整名单的选人接口回退，并不等于一个 HTTP 请求。
- 同局新名单即使总人数少于旧占位名单，只要有效身份数增加，也接收新名单；客户端未提供的位置不伪造身份。房间/名单无名称且缓存亦无已核验名称时显示“玩家名称暂不可用”，历史查询状态单独呈现。
- 新一局重新获得刷新预算。完成标记取决于本轮成功读取的名单，而不是旧缓存是否完整，避免首次失败后被上一局数据抑制重试。标准 5v5 以外的模式目前仍使用十人完成条件，但不会无限重试。
- “刷新对局名单”只取本地身份，不重置本局资料补齐预算。开局一轮结束后的缓存缺失项，用户通过完整 ID 或已知玩家查询按钮获取。
- 手动完整 ID、所选玩家查询及名单刷新共享单操作门控，单次上限 12 秒；已有可用战绩复用，缺少基础资料可在该预算内补齐，不重拉历史。手动返回的数据只按 PUUID 回填同一代快照，避免污染已经切换的对局；即便代际变化，仍可返回这次显式查询的结果。
- 完整 ID 在前端、引擎缓存键及数据源处清理复制方向标记/边缘空白，非法输入不请求；不删除名称内部空格或有区分意义的连接/变体字符。腾讯身份解析使用只读语义的 `POST /lol-summoner/v1/summoners/aliases`，JSON 数组只含一个 gameName/tagLine；恰好一个结果且 PUUID/名称/标签核验通过才继续战绩查询。无自动重试/旧 GET 回退，单次 HTTP 仍为 5 秒。LCU GET/身份 POST 共用安全错误处理，保留取消/超时分类，不暴露原始 URL、正文或网络错误；诊断只记录固定 profile 分类。
- 玩家资料路径统一串行调度：等待的手动请求优先、同连接/PUUID 在途历史请求合并。自动准备每次运行最多 45 秒、每玩家最多两次，普通英雄变更不取消有效任务。阶段/本地名单与玩家资料分开，避免慢战绩阻塞阶段检测；并非把所有本机 GET 都塞入同一队列。
- Participant/Profile/Scout仍使用五分钟有界内存缓存，强制刷新独立入口；重新发现连接、注销或赛前同连接账号变化时清空，旧连接结果不得写入新连接。只有BUG-0065定义的去身份化HistoryPage摘要可落盘，且重连后须重新核验PUUID。断线资料标旧，未知时间不视为新鲜。可选 `AccountSource` 借用已有赛前轮询核验身份，不在局内增加该查询。
- 资料增强是可选 `ProfileSource`：显式手动查询确认身份后（包括首次历史失败但身份已确认），用额外最多两秒且总查询仍不超过 12 秒的预算读取等级/段位/隐私和头像；也可独立更新（三秒预算）。未知不视为未定级，不由权限错误推断生涯隐私。字段兼容待实机。
- BUG-0046 的 LoadRanks/RankSource 保留为兼容能力，产品已由 BUG-0047 的 RefreshData 统一替代；独立调用仍受 3 秒手动门控/调度和连接校验约束。兼容 queues 数组/映射与 queueMap；空值/未知阶位不作为未定级。Profile 增加脱敏 rankMessage，字段合并按本次实际请求范围进行，未请求字段的值/时间不变；失败保留已有段位和旧时间，历史取写回时最新缓存。
- 显式打开成员详情/战绩页及缓存命中的手动查询经 EnsureProfile 补齐完整资料；腾讯 Profile 先基础/图片后段位，其中基础/图片最多使用 1.5 秒，剩余父预算仍可读段位。BasicProfile 是数据源内部基础能力，不再作为产品独立查询步骤。补取预算最多 3 秒，共享手动门控和串行调度。完整新鲜资料直接复用，缺失尝试同连接/玩家冷却 30 秒，明确“刷新数据”绕过冷却；换号清理。排队后/返回后核验连接，写回以当前缓存历史为准。前端只队列最近一次显式打开，同玩家在途去重，不由快照变化自动触发。

本机回环请求不等于完全没有外网消耗：LCU 自身可能访问远端服务。当前策略旨在限制后台工作，并未测量或证明 CPU、FPS 或延迟零开销。

### BUG-0047 玩家资料整体准备

用户最新反馈取代 BUG-0046 的段位独立按钮方案，以及早期“不自动取头像/段位”的限制。房间/选人仍复用原准备窗口（45 秒，历史原有每人两次限制），先历史后可选资料；资料每个已知身份最多一次、最多 10 人、每次最多 3 秒，不由换英雄或轮询重启。开局/局内启动保留每局一次、10 人/45 秒边界，先完成所有缺名/首批历史，再用剩余预算补头像/等级/段位/隐私，不延长总时间，不取后页/双方详情。阶段、连接、名单身份均在排队前后/写回核验；串行且手动优先，失败不循环重试。Profile 的基础查询/图片最多使用 1.5 秒，剩余父预算仍可读段位，避免图片阻塞整包。

EnsureProfile 现在补齐完整资料并复用完整新鲜缓存/30 秒失败冷却；显式 RefreshData 共用单操作门控与最多 12 秒，先刷新首批历史，再完整资料。任一部分失败保留另一部分成功结果和原始字段时间。资料不创建战绩标签，前后端以各自历史/资料时钟合并，避免在途结果互相覆盖。旧桥接能力保留兼容，但产品只提供一个刷新动作。

## 可复现验证和交付

Go 单元测试不依赖真实账号；浏览器烟测模拟绑定，覆盖 20 场样本、独立标签、模式筛选、局内名单变化、设置冲突/导出以及快览控件。隐藏原生双进程测试独立于真实应用标识。Windows GitHub Actions 模板保留在 `docs/ci/verify.yml.example`，尚未启用：当前 GitHub OAuth 凭据缺少 workflow 权限，服务端拒绝包含工作流的推送。没有自动扩权，也没有换凭据绕过。模板仅计划验证 dev，不创建 release、不推 main；当前验证证据均为本地结果。

`scripts/build.sh` 将提交号/脏状态和 UTC 构建时间注入二进制；设置中可查看，帮助区分实际启动版本。`cmd/perfprobe` 用 Windows 进程计数采样指定 PID 及其可读后代（包括 WebView2）；隔离离线模式不发现 LCU、不注册快捷键，35 秒自退出。它不修改系统策略、不结束原有进程。现有离线结果与限制见 PERFORMANCE.md，不代表真实游戏验证。

## 技术权衡

Wails + Go 便于编写本机客户端适配和低资源后台逻辑，Vue 3 + TypeScript 便于迭代界面。Wails 3 目前仍是 beta；采用它是为了多窗口、单实例和全局快捷键能力，这些行为仍需 Windows 和游戏环境实测。BUG-0045 根据新的按住快览需求，仅在临时模式恢复鼠标穿透；手动模式可交互。若 beta 稳定性不足，迁移到稳定桌面框架可能成为发布前任务。

没有把客户端 API 查询失败推断为“生涯不公开”。也没有声称选人阶段一定可以获得双方十人身份；可见身份随模式、客户端版本和匿名化策略变化。

## Review 后的数据浏览与状态修复

快照与每位玩家携带连接编号；旧连接快照可显示，但不能成为新来源的有效身份或缓存。界面按连接编号与获取时间合并列表、标签和详情；错误绑定发起操作的玩家。选人重试沿用本次会话的期限与尝试数，短暂阶段失败可由后续正常轮询恢复。

分页通过可选 `HistoryPager`，每次 20 条、最多 1000 条，以原始返回量推进位置。`useHistoryBrowser` 将显示页（每页 20 场）与分析样本（所选模式最近 N 场，N 为 10/20/30/40/50，默认 20）分开；胜率/KDA、近况和常用英雄共用分析样本，翻页不改变它。未查到底的页数只是已知下界，不当作全部历史总数。

分页控件与列表同属 `history-panel`，只滚动记录；指定页码输入由前端校验整数及范围，缓存完整页不发请求。尚可显式查询时页码上限 50，源停止或离线后上限为已有页数；这不是全账号历史总页数。未缓存目标仍通过同一有界扫描器顺序填充，暂停保留 browseTarget，继续时沿已有游标查找；目标不存在时保留当前页。输入草稿在玩家、模式、来源戳或实际页变化时同步复位。

国服实测 LCU 的 begIndex 可被忽略而反复返回首页。因此 `History`（含自动准备）仅取 LCU 首批 20 场；显式 `HistoryPage` 改用 SGP SUMMARY 的 startIndex/count。Go 内核验 currentPlatformId 与客户端 ServiceEndpoint 完全匹配的腾讯 HTTPS 域名，普通 TLS、不跟随重定向、不继承代理；只在该官方服务携带内存 entitlement accessToken，最多复用两分钟，ResetIdentity 清除。认证/配置核验只在首次或短时缓存失效的显式调用进行，不增加自动刷新任务。

SGP 摘要使用扁平参与者统计和 metadata+json 信封；适配器验证 product/info_type、当前大区、比赛编号及目标 PUUID 后复用可空统计解析，规范化技能与符文。请求类别固定 sgp-history，不记录 URL、正文、身份或授权。不可用时单次 LCU 前缀读取至多 50 场，切出已读范围，返回 limitReason；这表示来源上限，不是账号历史终点。前端拒绝全重复页且不更新位置/数量，受限时不冒称模式无记录。

来源没有可靠的按模式分页契约，不能把首批混合历史筛选后的数量冒充该模式最近 N 场。BUG-0065起，首页/查询空闲后可低优先级顺序准备单双排与灵活；显式切换模式/场数、翻页、继续或补齐沿用相同游标与精确口径，满足分析与目标页所需数量后停止。样本补齐连续串行到目标模式数量、来源耗尽/受限或最近 1000 条混合记录；90 秒后不再启动下一次请求，单次仍受后端超时约束。远页跳转保持单轮五页/15 秒，继续保留目标与游标。用户停止、切人或隐藏工作区后不再启动下一次请求；已有结果保留。模式稀少、范围耗尽、失败和实际不足均有可见状态，不用其他模式补数。

前端按比赛 ID 去重；每工作区/玩家保存筛选、样本数、分页、展开、游标、额外记录和停止状态，后端另按BUG-0065保存去身份化页面快照；新局/连接切换仅重置抽屉状态，查询标签保留。缓存完整页不重复请求；异常游标不推进位置，失败不清空当前页。历史后台状态不进入全局手动忙状态，后端统一调度允许搜索/资料/刷新/详情抢占自动请求。切人/离开工作区停止旧任务继续扫描，已发出的响应只允许写入原身份的本地页缓存，不污染新玩家或另一工作区；来源戳变化拒绝前端旧响应。连接失效只浏览已有缓存。

历史专用 `RefreshHistory` 使用当前连接内已核验身份，不重复名称搜索或可选资料增强，前端区分顶部查询和玩家刷新状态。刷新清空前端分页回第一页，保留模式与目标样本数；空闲预热或缺样本操作从本地游标继续，不把刷新按钮本身延长为整段扫描。

`MatchDetailSource` 仅在点击读取双方详情时调用；检查比赛编号与目标身份，整场参与者单独有界缓存。团队占比必须具备完整标准队伍及相应字段；未知值不补零。可选 `ProfileSource` 支持独立资料更新；privacy 只接受身份一致的 PUBLIC/PRIVATE，不能从战绩失败推断。

资料按字段记录成功时间及本次状态（ready/retained/unavailable）。独立更新资料不要求历史时间变动；前端分别选择两者最新版本，保留字段带旧值标识。头像只按核验后的 profileIconId 请求本地游戏资源，限制体积和解码尺寸；以内存数据 URI 传递，不保存文件。编号变化而新图失败时不能沿用旧图。此功能没有加入赛前自动准备。

战绩摘要和双方详情共用解析：地图、teamPosition、客户端线路、六个符文和主副系、gameEndedInEarlySurrender 只有明确返回才展示。线路不推断位置，提前结束不推断确定重开，不改变现有统计分母。符文中文名称随包提供，未知编号就近显示。展开摘要不自动请求完整详情。

`PhaseEventSource` 为可选会话能力。每连接至多一条阶段流，合并唤醒信号，使用连接编号/订阅序号拒绝迟到回调；换号、断线和退出取消旧流。诊断中的 phase-events 只统计握手次数、耗时与状态码，不记录事件内容；握手成功不保证客户端已接受主题或持续发送通知，正式支持仍需实机核验。
