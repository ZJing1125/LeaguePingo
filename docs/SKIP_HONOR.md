# 自动跳过点赞（BUG-0082）

“设置与诊断 → 游戏辅助 → 赛后点赞与下一局”提供独立的“自动跳过点赞”开关，默认关闭，旧配置升级不自动开启。它可以单独使用，只结束点赞页；是否返回房间、是否排队仍由原有两个开关决定。三个赛后开关和排队延迟在同一次保存成功后一起应用，失败恢复原值，恢复默认只是待保存草稿。

## 执行

沿用既有赛后任务：必须在本连接、账号观察过InProgress并冻结同局复盘；普通房间、退选、观战、结算阶段才启动助手不触发。每局一轮，关闭/取消后同局不重启；下一场可重新执行。没有增加常驻任务、局内资料读取或SGP请求。

只新增本机固定GET `/lol-honor-v2/v1/ballot` 与无请求体的POST `/lol-honor/v1/ballot`。只解析比赛编号及是否已存在用户点赞，候选玩家和身份在瞬时解析后丢弃，不进入前端、缓存、设置或诊断。缺失/非法字段、接口不支持和其他比赛的ballot不能当作可提交的空票。

找到本局未选择对象的ballot后，主窗/展开侧栏同步显示3秒倒计时，可取消本次。提交前再次核验账号、阶段和最新ballot；若用户已手动选择，助手不提交，在原有预算内等待手动完成。不调用honor/honor-player，不发送任何接收者或点赞类型，不模拟点击、注入或跳过奖励页。

POST每局最多一次。无论响应成功或超时，之后核对ballot清空且进入EndOfGame，或实际进入Lobby，才继续后续动作；不能只凭200/204判定已关闭页面。5秒未确认则停止本次流程并提示手动检查，不重发、不绕过到返回/排队。关闭功能不能撤销客户端已处理的请求。

WaitingForStats不读取或提交荣誉页，仍先等待复盘结算；PreEndOfGame尚无ballot时最多沿用原15秒等待，明确无活动页后保持原返回行为。全轮仍90秒、每请求1秒，ballot读取含提交前复核最多24次，等候使用原约1秒探测间隔。已手动选择时也受上述总期限/读取上限约束，不能无限等待。错误、账号/连接/比赛/阶段变化、退出或取消拒绝迟到结果。返回/搜索仍各最多一次，房间队长/就绪/同模式门控保持不变，详见[赛后流程](POST_GAME.md)。

## 验证

Go合成与本机HTTPS覆盖：默认无请求、独立仅跳过、跳过后返回/排队、成功响应丢失只提交一次、阶段未切换不误判成功、接口不支持、比赛/账号不符、手动选择及提交前竞态、取消/禁用/换号迟到、下一局重新执行、无点赞页、WaitingForStats与读取上限。设置及服务出口覆盖独立持久化、旧配置默认关闭、失败不生效。浏览器桥接覆盖三个独立开关、保存/草稿/失败、跨窗倒计时与取消、未知结果、深浅主题和280/880/1280布局。

接口参考为[LeagueAkari HonorHttpApi](https://github.com/LeagueAkari/LeagueAkari/blob/56cdfde00e56148f4641d1a8cf86acb66e903124/src/shared/http-api-axios-helper/league-client/honor.ts)及其独立提交步骤。本批独立Go实现，无插件运行依赖或上游源码复制。公开源码存在该端点不等于腾讯当前客户端的空票行为已核验。Windows原生自动验证以本提交CI为准；国服实机跳过效果、实际ballot/阶段语义仍待用户按R1的P6/P7复验，原P1/P2反馈不推广为新增功能通过。
